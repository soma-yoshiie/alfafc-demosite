# スマホ版UI再設計 v2 仕様（下部タブをPCの大枠に合わせる／チームの整理）

作成：2026-09-13／設計：fable5／実装：sonnet5／レビュー：opus5
前提：v1（`specs/mobile-redesign.md`）の上に積む差分仕様。v1 の §2（配色・部品）・§8（AIっぽさ排除チェックリスト）・CSS の約束（`@media` 9本、PCブロックは「mobile-redesign PC reset」セクション以外触らない、スマホ限定は `.mhead` の有無で判定）はそのまま有効。
対象：幅1024px未満。PC（≥1024px）のDOM・見た目・挙動は変えない。

## 0. ユーザー指示（原文の要点）

1. 下部タブは5個で確定。PCの大枠（ホーム／コーチング／チーム／その他）に合わせ、スマホは **ホーム／コーチング／サッカーノート／チーム／その他**。サッカーノートはスマホだけ「チーム」の中に入れず大枠にする。チームの中にチャットを入れる（PCと同様）。その他＝設定とコーチラボ。
2. チームを開いたらカレンダーが表示される（チームの中の「ホーム」は要らない）。
3. チームの並びは「カレンダー／試合記録／名簿／チャット」。項目は今後移動するかもしれない（未確定）ので、並びの変更が容易な作りにする。
4. チームのUIは緑が多く、ごちゃごちゃしているので直す。**勝敗の「勝」マークの緑は残す**。

## 1. 下部タブ（`ConsoleShell.tsx` の `.mtab`）

| 役割 | タブ（左から） | 遷移先 | アクティブになる画面 |
|---|---|---|---|
| スタッフ | ホーム／コーチング／ノート／チーム／その他 | `home`／`coaching`／`notebook`／`team`／`other`（新設） | ホーム=`home`。コーチング=`coaching`,`board`,`setpiece`,`drill`,`library`。ノート=`notebook`。チーム=`team`,`chat`。その他=`other`,`articles`,`settings` |
| 選手・保護者 | ホーム／ノート／チーム／その他（4つ） | `home`／`notebook`／`team`／`other` | ホーム=`home`,`board`,`drill`,`library`。ノート=`notebook`。チーム=`team`,`chat`。その他=`other`,`articles`,`settings`,`setpiece` |

- 「チャット」タブは廃止（チームの中へ）。ラベルは「ノート」（4文字以内。v1 §8-5-23）。「その他」のアイコンは `icons.tsx` の線画（横三点 `IconMore` を新設、24px）。
- 選手・保護者はコーチングが無いため4つ（ユーザー指示の「5個」はスタッフの構成として解釈。要確認事項として報告に残す）。
- タブ定義は `MTAB_*` の Set と配列で持ち、順序・所属の変更が1箇所で済むようにする（§0-3 の「未確定」対応）。

## 2. 「その他」ハブ（新設 `ScreenName` `"other"`、`components/OtherHub.tsx`）

- ヘッダー「その他」（戻る無し＝タブ直下）。
- 行リスト（`MobileRows` の `MenuGroup`/`MenuRow` を再利用）：
  - スタッフ：コーチラボ（指導者の記事を読む・書く・売る）／設定（チーム名やプラン、公開範囲を変更する）
  - 選手・保護者：コーチラボ／セットプレーデザイン（CK・FK・スローインの動きを設計して共有する）
- 末尾に「ログアウト」（テキストボタン。ホーム末尾の `mhome-logout` と同じ様式・同じ処理）。ホーム末尾のログアウトは残してよい。
- コーチラボ・設定・（選手の）セットプレーデザインのスマホ「‹ 戻る」は `other` へ（`navFrom` の仕組みを流用。ホームの行から開いた場合は `home` へ）。
- PCレールには出さない（PCは変更なし）。

## 3. チーム画面（`TeamHub.tsx`、スマホ）

### 3-1. タブ構成と初期タブ

- スマホのタブ配列（`tabs`）：スタッフ＝**カレンダー／試合記録／名簿／チャット**、選手・保護者＝**カレンダー／試合記録／チャット**。「ホーム」「出欠」はスマホのタブから外す（PCは元々サブメニューがカレンダー／試合記録／名簿で、出欠は予定詳細の「記録を見る・編集」経由。スマホも同じにする）。
- 初期タブ＝カレンダー（`useState<Tab>(() => "cal")`。PC は既に `cal`）。`teamIntent` の `home`/`att` はスマホでもカレンダーへ丸める。
- タブの定義は `[Tab, string][]` の1配列を並べ替えるだけで順序が変わるようにし、`chat` を `Tab` 型に追加する。PC のサブメニュー（`subnavTabs = ["cal","rec","ros"]`）は変更しない。
- `HomeTab`（次の予定／連絡／試合サマリー）はPCでも到達不能（intent の home→cal 丸め済み）なので **削除**し、関連CSS（`.hometab` `.httop` `.htmain` `.htside` `.quickrow` と PC ブロック内でそれらだけを参照する行、`.teamapp:has(.mhead) .quickrow …`）も削除する。`AttendanceTab` はPCで使うので残す（スマホからの入口だけ無くなる）。

### 3-2. チャットをチームの中へ

- `TeamHub` に `chat` タブを追加し、`ChatScreen.tsx` の `CoachConversations`（コーチ）／`PlayerChat`（選手）を export して、そのままタブ本体として描画する（会話をタップすると既存どおり `board.openSheet({type:"chat", chatTo})` のシートが開く）。
- チャットタブの上部に **「連絡」**（旧ホームタブの内容）を移す：見出し「連絡」＋「すべて見る ›」（`annList` シート）、スタッフには「＋ 連絡を送る」（`announce` シート）、最新2件の `AnnCard`。連絡が0件なら「連絡はまだありません。」の1行。
- スマホで `setScreen("chat")` を呼んでいる箇所（ホームの行「チャット」、選手ホームの行、通知等。`grep -n 'setScreen("chat")'` で全件）は、スマホでは `board.setTeamIntent({ tab: "chat" }); board.setScreen("team")` に置き換える（PC分岐は `setScreen("chat")` のまま）。`BoardProvider` に `openChat()` のような小さなヘルパーを足してよい（内部で `usePc` 相当の判定はせず、呼び出し側の `pc` 分岐で使い分ける）。
- `ScreenName` の `"chat"` と `ChatScreen` はPC用に残す。スマホで万一 `chat` 画面が表示された場合もヘッダーにチームのセグメント（チャットがアクティブ）を出す必要はない（到達経路を無くす方が優先）。

### 3-3. ヘッダーと主操作（緑の大ボタンをやめる）

- `MobileHeader` のタイトル：スタッフ「チーム運営」、選手「チーム」。サブタイトルは出さない。
- 右のアクション（`MobileHeaderAction`、44×44、`--accent` の線画）をタブ連動で1つだけ出す：カレンダー＝「予定を追加」（`IconPlus`）、試合記録＝「試合結果を記録」（`IconPlus`）、名簿＝「選手を追加」（`IconPlus`）、チャット＝「連絡を送る」（`IconPlus`）。`aria-label` にその文言を入れる。スタッフのみ。
- これに伴い、タブ本体の中の全幅の緑ボタン（カレンダーのリスト表示末尾「＋ 予定を追加」、試合記録末尾「＋ 試合結果を記録」、名簿の「＋ 新規選手を追加」）は **スマホでは描画しない**（`pc` 分岐で PC はそのまま）。
- `rolebar`（「表示：スタッフ（管理）▾／全員を管理」）：スマホでは **通常時は出さない**。代わりに、
  - 名簿タブの末尾に「選手・保護者の見え方を確認」という1行（既存の `select` をそのまま置く。ラベルは `--mut` 12px）。
  - 選手として閲覧中は、セグメントの上に帯「〇〇さんとして閲覧中 ・ スタッフ表示に戻す」（`--accent-tint` 地、`--accent` 文字、戻すはボタン）。名簿タブが隠れても戻れる。
  - 選手ログイン時の「〇〇さんとして閲覧できます」の帯はスマホでは出さない。
  - PC の `rolebar` は変更しない（`pc` 分岐）。

## 4. ホーム（スマホ）の行リスト

- グループと行はPCレールの並びのまま（コーチング／チーム／その他）。変更点：「チャット」行はチーム画面のチャットタブを開く（§3-2）。「チーム運営」行の説明は「予定・出欠・試合の記録・名簿」に。
- 選手ホームの行：サッカーノート／チーム／チャット（チームのチャットタブ）／セットプレーデザイン（変更なし）。

## 5. 変えないもの

- PC（≥1024px）のDOM・見た目・挙動（レール、サブメニュー、チャット画面、チーム運営の3ペイン、rolebar、CTA）。
- 内部ロジック（保存キー、出欠・試合の集計、通知）。
- ピッチの緑、`.mres.w` の緑。

## 6. 実装分割

- **Phase A（構造）**：§1・§2・§3-1・§3-2・§3-3・§4。`npx tsc --noEmit`、`@media` 9本、`scratchpad/tools/mobile_audit.js` の `SEGS.team`／下部タブ名を更新して全画面描画確認。
- **Phase B（整理）**：§3-4 と、はみ出し・タップ領域・緑残存の自動検査。
- **Phase C（レビュー）**：opus5 ×3 並列（目視／コード差分／PC不変＋実測）。
- **Phase D（修正）**：致命・要修正の反映と最終検証（最大2周）。

## 7. 検証手段（`scratchpad/tools/`）

- 開発サーバーは常時起動（http://localhost:3000）。実装者は起動・停止・`next build` をしない。
- `node mobile_audit.js <outdir>`：スマホ全画面撮影＋横はみ出し検出（`overflow_report.json`）。変更前＝`base_m/`。
- `node pc_baseline.js <outdir>`：PC 10画面撮影。変更前＝`pc_base/`。`python3 compare.py diff pc_base <outdir> <diffdir>` で差分（日時・カウントダウン・「最新の動き」は動的差分として許容）。
- `python3 compare.py sheet <dir> <out>`：コンタクトシート。`python3 compare.py pair <before> <after> <out>`：左右比較。

## 8. 受け入れ基準

1. 下部タブがスタッフ＝ホーム／コーチング／ノート／チーム／その他、選手＝ホーム／ノート／チーム／その他で、アクティブ表示が §1 の対応表どおり。
2. チームを開くとカレンダーが表示され、セグメントがカレンダー／試合記録／名簿／チャット（選手はカレンダー／試合記録／チャット）。「ホーム」「出欠」のタブが無い。出欠は予定詳細から開ける。
3. チャットがチームのセグメントから開け、「連絡」がその上部にある。ホームの「チャット」行からも同じ場所に着く。
4. 「その他」にコーチラボ・設定（選手はコーチラボ・セットプレーデザイン）とログアウトがある。
5. チーム画面のスマホで、緑は「勝」だけ（自動走査で確認）。全幅の緑ボタンと常時表示の rolebar が無い。
6. 全画面で横はみ出しゼロ。`tsc` 成功。`@media` 9本。PC 10画面が変更前と一致（動的差分を除く）。
7. v1 §8 のチェックリストに新たな違反が無い。
