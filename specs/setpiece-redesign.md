# セットプレーデザインの整理（種別の絞り込み・位置から作る FK／スローイン・ボールの軌道・PA 拡大・操作列の整理）仕様

作成：2026-09-21／設計：fable5／実装：sonnet5／レビュー：opus5
ブランチ：feature/groups-everywhere。対象：`components/SetPieceBoard.tsx`・`SetPieceBar.tsx`・`Header.tsx`・`Pitch.tsx` まわり・`BoardProvider.tsx`・`lib/`。スマホ・PC 両方。

## 0. ユーザー指示（原文の要点）

1. ゴールキックと PK は要らない。
2. CK の「ニア狙い」「ファー狙い」などは要らない。
3. 相手だけ・味方だけをいじるボタンが、今は「オフにする側をタップ」になっている。逆にしてほしい。
4. FK は、選んだらまず **どの位置から蹴るか** を選ぶ。そのうえで **どこに・どんな軌道で蹴るか** を調整できるようにする。
5. スローインは、**サイドラインのどの位置か** を選ぶ。その後、どこに・どんな軌道で投げるかを調整できるようにする。
6. ペナルティエリアを拡大表示できるようにする。
7. 上の機能の選択肢がごちゃごちゃしているので、しまえるようにする（全部をひとまとめにしまうと分かりにくいのでやめる）。
8. 新規作成は一番右上の「共有」「ライブラリ」のところに置く。

## 1. 種別と配置の作り方

- 種別は **CK／FK／スローイン** の 3 つ（`KIND_ORDER`）。ゴールキック・PK は操作列に出さない。型 `SetPieceKind` と旧プリセットの定義は残す（保存済みの文書・共有データを開けるようにするため）。旧種別の文書を開いたときは種別チップがどれも選択されない状態でよい。
- **プリセットのチップ行（「CK：ニア狙い」など）を廃止**する。代わりに「種別 × 攻守 × 人数（× 位置）」から **基本配置** を作る。新規 `lib/setPieceLayouts.ts`：

```ts
export interface SetPieceLayoutInput { kind: "ck" | "fk" | "throwin"; side: "attack" | "defense"; format: 8 | 11; origin?: Point }
export interface SetPieceLayout { ball: Point; view: PitchViewMode; slots: { x: number; y: number; role: Position }[]; opps: { x: number; y: number }[] }
export function buildSetPieceLayout(input: SetPieceLayoutInput): SetPieceLayout
```

  - CK：既存の `ck-near-attack`（攻撃）・`ck-zone-defense`（守備）と各 `-11` の **座標だけ** を使う（ゾーンの網掛け・「ニア」「キッカー」などの図形とメモは付けない）。`origin` は右コーナー固定（左は既存の「左右反転」）。
  - FK・スローイン：§3 の生成規則。
- `BoardProvider`：`applySetPieceLayout(input)`（盤面を基本配置で置き換える。`setPiece` メタは `{ kind, side, format, presetId: undefined }`、`moves`・図形・描き込みは空に）と、`newSetPiece` を同じ入力で呼べる形に。既存の `applySetPiecePreset` は残す（旧データ用）。context の公開箇所すべてに足す。
- 種別・攻守・人数のチップを押すと基本配置を適用する。**いまの盤面に手が入っているとき**（`moves`／描き込み／図形が 1 つでもある、または保存済みの文書を開いている）は `window.confirm`「配置を作り直します。いまの配置と動きは消えます。よろしいですか？」で確認する。直前の状態は 1 件だけ覚えて「元に戻す」で **盤面そのもの** を戻す（プリセット id の再適用ではなく、直前の `BoardState` のスナップショットを戻す）。
- 8 人制⇔11 人制の切り替えは、種別・攻守・位置を保ったまま基本配置を作り直す。

## 2. 「動かす」の切り替え（旧「固定」）

- ラベル **「動かす」** ＋ 3 択の分割ボタン：**両方｜味方だけ｜相手だけ**（既定＝両方）。「相手だけ」を選ぶと味方のトークンは動かせない（＝旧 `lockOwn`）。「味方だけ」はその逆。
- 実体は従来どおり `SetPieceBoard` のルートの `.sp-lock-own`／`.sp-lock-opp`。編集・アニメ両モードに出す。

## 3. 位置から作る FK・スローイン

### 3-1. 位置を選ぶ

- FK またはスローインを選ぶ（または新規作成する）と **位置を選ぶモード** に入る：ピッチを全体表示にし、ピッチの上に案内の帯「キックの位置をタップしてください」／「スローインの位置（サイドライン）をタップしてください」＋「やめる」。トークンは薄く表示し、ドラッグは無効。
- FK：タップした点がボールの位置（x 2〜98・y 2〜98 に丸める）。攻撃は相手陣（y ≥ 50）、守備は自陣（y ≤ 50）を想定するが、どこでも置ける。
- スローイン：タップした点から **近い側のサイドライン** に吸着（x は 0.8 か 99.2、y はタップした y を 2〜98 に丸める）。
- 位置が決まると基本配置を生成して適用し、位置を選ぶモードを抜け、「ボールの軌道」のグループ（§5）を開く。
- あとから変える：「種類」グループの **「位置を選び直す」**。選び直すと選手の配置は作り直す（§1 の確認あり）。ボールのトークンを直接ドラッグして微調整するのは従来どおり可能（配置は作り直さない）。

### 3-2. 生成規則（`lib/setPieceLayouts.ts`。純粋関数・テスト可能に）

座標系：x 0（左）〜100（右）、y 0（自陣ゴール）〜100（相手ゴール）。ピッチは 105m × 68m 相当（y の 1 ＝ 1.05m、x の 1 ＝ 0.68m）。攻撃＝相手ゴール（y100）へ向かう。守備は同じ規則を上下反転（y → 100 − y）して味方と相手を入れ替える。

- **FK（攻撃）**：キッカー 1 人をボールの手前（ゴールと反対側へ 2）。ゴール中心（50,100）までの距離 d（m）：
  - d ≤ 30：相手の **壁**（11 人制：d ≤ 22 で 4 人・それ以外 3 人／8 人制：2 人。ボールとゴールのニア側ポストを結ぶ線上、ボールから 9.15m。横に 1.2 間隔）。相手 GK はゴール前（x 50 付近・y 98.5）。味方はゴール前に 3〜4 人（PA 内のオフサイドにならない位置に横並び。相手が 1 人ずつ付く）、こぼれ球に 1〜2 人（PA の外）、残りは後方のリスク管理（自陣寄りに 2 人＋GK）。
  - d > 30：壁は 1 人。味方・相手はボールより前の中央〜ゴール前に均等に並べ、後方にリスク管理。
  - ボールがサイド（x < 25 または x > 75）：壁は 1〜2 人、ゴール前の人数を 1 人増やす。
- **スローイン（攻撃）**：スローワー 1 人（ボールの位置・ラインの外側に 0.8）。近くの足元に 2 人（ボールから 6〜10 の距離で前後）、裏へ 1 人、中央に 1〜2 人、残りは後方と GK。相手は各味方に 1 人ずつ（ゴール側に 2〜3 ずらす）＋GK。
- トークン同士は最低 3.2 離す（重なったら後から置く方をずらす）。すべて 1.5〜98.5 の範囲に収める。人数は `format`（8／11）ぴったり、役割（`role`）は GK 1 人＋それらしい役割。
- `view`：ボールが y ≥ 58 なら `boxatk`、y ≤ 42 なら `boxdef`、それ以外は `full`。

## 4. ボールの軌道（キック／スロー）

- 対象：CK・FK・スローイン。実体は **場面 0 のボールの最初の move**（`actor:"ball"`）。専用の保存形式は足さない（3D 再生・アニメ・書き出しがそのまま使える）。
- 「ボールの軌道」グループ（§5）を開いている間、ピッチに **軌道の線**（ボール → 狙う場所。`PathLayer` のボールの線と同じ色の文法）と **狙う場所のハンドル**（ドラッグ可・タップ領域 44px）を出す。まだ move が無ければ既定の狙い（攻撃＝ゴール前の中央 (50, 92)。守備＝同じ規則の反転）で作る。
- 操作：
  - **狙う場所**：ハンドルをドラッグ。
  - **軌道**：3 択 **グラウンダー｜ライナー｜浮き球**（`BallTrajectory` の `ground`／`driven`／`lofted`）。スローインは表示名を **足元へ｜速く｜山なり** に。
  - **曲がり**：5 段階 **左に大きく｜左｜まっすぐ｜右｜右に大きく**（スローインは出さない）。線は二次ベジェを 12 点に分割した `path` にする（横ずれ＝距離 × 0.12／0.25）。
  - **消す**：軌道の move を削除。
- 受け手（`to`）は自動：狙う場所がゴールの枠内（y ≥ 99 かつ x 44.5〜55.5）なら `"goal"`、そうでなければ半径 5 以内の最も近い味方の枠、居なければ未設定。所要時間 `dur` は距離と軌道から決める（グラウンダー 1.0s/30m、ライナー 0.8s/30m、浮き球 1.4s/30m を目安に 0.5〜3.0s）。
- ボールのトークンを動かしたら軌道の始点も追従する。アニメのスタジオでこの move を編集・削除しても壊れない（無ければ「まだ軌道がありません」＋「軌道を作る」）。

## 5. 操作列をグループに分けてしまえるようにする

- 操作列を **4 つのグループ** に分ける。各グループは見出しボタン（名前＋いまの状態の要約＋開閉の印）と、その下の中身の行。**グループごとに** 開閉でき、複数同時に開ける。開閉の状態は `localStorage`（`soccer_tactics_spbar_v1`）に保存。
  1. **種類**：種別（CK／FK／スローイン）・攻守・人数・「位置を選び直す」（FK／スローイン）・「元に戻す」。要約の例「FK・攻撃・11人制」。
  2. **ボールの軌道**：§4。要約の例「浮き球・右に曲げる」／「未設定」。
  3. **表示**：表示範囲（§6）・左右反転。アニメ中はここに「ルート表示／描き込み／残像」。要約の例「ゴール前」。
  4. **描く・動かす**：＋相手・ペン・図形・アニメ・「動かす」（§2）・3D。要約の例「相手だけ」（「両方」のときは要約なし）。
- 既定：初めて開いたときは「種類」だけ開く。PC は見出しボタンを 1 行に横並び、開いたグループの中身をその下に積む。スマホは見出しの行を横スクロールにせず 2×2 で並べ、中身は下に積む（中身の行は折り返し。横スクロールにしない）。
- 見出しボタンは `aria-expanded`・`aria-controls`。PC は角丸 8px・高さ 32px、スマホは高さ 44px。中のチップは既存の `.chip`／`.fmini` の文法（PC は四角）。
- 操作列の右端が画面からはみ出さないこと（現状は PC で「3D」が切れている）。
- 選手（スタッフ以外）には従来どおり操作列を出さない。

## 6. 表示範囲とペナルティエリアの拡大

- 表示範囲は 3 択：**全体｜ゴール前｜PA 拡大**。
  - ゴール前＝既存の `boxatk`／`boxdef`（どちらのゴールかは攻守ではなく **ボールに近い側**：ボール y ≥ 50 → 相手ゴール側）。
  - **PA 拡大**＝新しい `PitchViewMode` `"paatk"`／`"padef"`：ペナルティエリアと周辺（x 14〜86・ゴールラインから y 方向に約 30）を画面いっぱいに表示。
- 実装の方針：y の変換（`lib/pitchView.ts`）は `paatk`＝`boxatk`、`padef`＝`boxdef` と同じ式のままにし、**横の切り出しはピッチの描画層を CSS で拡大（scale ≈ 1.39、原点はゴール側の辺の中央）して外枠で切り抜く**。トークン・ボール・ハンドル・文字は拡大されすぎないよう逆倍率を掛けて画面上の大きさを保つ。ポインタの座標変換（`usePointerDrag`・ペン・図形・軌道のハンドル）が拡大中も正確であること（変換は拡大後の要素の `getBoundingClientRect` を基準にする）。枠の外に出るトークンは見えなくてよい。
- 書き出し（PNG／GIF）と 3D は `paatk`→`boxatk`、`padef`→`boxdef` として扱う（切り出さない）。戦術ボード（通常の文書）には PA 拡大を出さない。

## 7. 新規作成を右上へ

- 操作列の「新規作成」を外し、右上のアイコン列に **新規作成**（`IconPlusSquare`。`title`「新規作成」）を足す。PC は 保存・新規作成・戦術アニメ・ライブラリ・共有 の順。スマホは「…」のメニューの先頭に「新規作成」。**セットプレーデザインの画面だけ**（戦術ボードの「新規」は操作列のまま変えない）。
- 動作：いまの種別・攻守・人数で新しい文書（保存中の ID を外す）。FK／スローインは位置を選ぶモードに入る。手が入っているときは §1 と同じ確認。

## 8. 変えないもの

- 3D の再生（`SetPiece3D`）・アニメのスタジオ・ライブラリの保存形式（`SavedSetPiece`）・共有データの形式。旧プリセットで作った文書は開いてそのまま編集できる。
- 戦術ボード（通常の文書）の見た目と操作。`Pitch` まわりは共用なので退行させない。

## 9. CSS の契約

- `app/globals.css` の行頭 `@media` は 9 本のまま。新規ルールは基底、PC だけの調整は 2 つ目の PC ブロック末尾の `/* === mobile-redesign PC reset === */`。色はトークンのみ（新規 hex・グラデーション・絵文字は禁止）。文字 12px 以上、スマホのタップ領域 44px 以上、緑（`--primary`）は主ボタンだけ。PC の操作部品は四角（`--r-md`）。スマホ 390px で横はみ出しゼロ。

## 10. 受け入れ基準

1. 種別が CK／FK／スローインの 3 つだけ。プリセットのチップ行が無い。CK を選ぶと図形なしの基本配置になる。旧プリセットで保存した文書（ゴールキック・PK を含む）をライブラリから開ける。
2. 「動かす：両方｜味方だけ｜相手だけ」。「相手だけ」で味方が動かず相手が動く。逆も同じ。
3. FK を選ぶ → 位置を選ぶ案内 → ピッチをタップ → その位置にボールとキッカー、距離に応じた壁、ゴール前の選手が並ぶ（8 人制・11 人制とも人数ぴったり・重なりなし・枠内）。「位置を選び直す」で作り直せる。守備でも同じ。
4. スローインはタップした点が近い側のサイドラインに吸着し、スローワーと受け手が並ぶ。
5. 「ボールの軌道」で狙う場所をドラッグでき、軌道 3 種と曲がり 5 段階が線と `moves` に反映され、アニメと 3D の再生でその弾道になる。スローインは表示名が変わり曲がりが無い。
6. 表示範囲 3 択。PA 拡大でペナルティエリアが画面いっぱいになり、拡大中もトークンのドラッグ・ペン・図形・軌道のハンドルがずれない。PNG 書き出しが壊れない。
7. 操作列が 4 グループで、グループごとに開閉でき、要約が出て、再読み込みで開閉が保持される。PC・スマホとも操作列がはみ出さない。
8. 新規作成が右上（PC はアイコン、スマホは「…」の先頭）にあり、操作列には無い。戦術ボードは変わらない。
9. `npx tsc --noEmit` 成功、`@media` 9 本、スマホ全画面ではみ出しゼロ、戦術ボードほか他画面は変更前と一致（日付・時刻由来を除く）。

## 11. 検証手段

- 開発サーバー http://localhost:3000（落ちていたら `(nohup npm run dev > /tmp/alfa_dev.log 2>&1 &)`）。`next build` 禁止。
- ツール：`scratchpad/tools/`（`mobile_audit.js <outdir>`、`pc_baseline.js <outdir>`、`compare.py <dirA> <dirB> <outdir>`、雛形 `p2_verify2/lib.js`）。変更前の基準は `p5_base/pc`・`p5_base/m`。**起動から保存データの読み込みまで 3〜4 秒かかるので、goto／reload の後は 6 秒待つ。** PC のピッチ上のタップ・ドラッグは `pointerType:"mouse"` のポインタイベントが必要。`window.confirm` は `page.on("dialog", d => d.accept())`。
- 生成規則は Node で直接呼んで検査できる（`npx tsx` は入れない。`lib/setPieceLayouts.ts` は型以外の import を持たない純粋関数にして、検証時は TypeScript を `npx tsc --outDir` で一時出力するか、ブラウザの `page.evaluate` から盤面の状態（`localStorage` の `soccer_tactics_setpiece_work_v1`）を読んで検査する）。

## 12. 実装後の改訂（2026-09-21・統括）

実装とレビューを経て、次の点を仕様から改めた。コードとこの節が正。

- **§3-2 生成規則**：「最低 3.2 離す」「表示範囲へ比例圧縮」はやめた。データ座標や実メートルの間隔では、スマホ（ピッチ幅 302px・トークン径 51px）で重なりが残り、圧縮すると後方の選手が同じ高さに固まったため。`lib/setPieceLayouts.ts` は 2 段構成にした。
  1. **行のテンプレート**：ゴール前の列・こぼれ球の列・後方の列を最初から読める間隔で置く。後方 2 人と GK は表示範囲のいちばん下の列に横へ広げる。
  2. **読みやすさの検査**（`settle`）：スマホ 390 と PC 1440 の両方の px 換算で、円どうし・味方の名前ラベル（味方のトークンは「円＋役割＋名前」の高さ 95px の箱がデータ点を中心に描かれる＝円は点より 22px 上、ラベルは 31.5px 下）・ボールとぶつからない最寄りの位置へ、横へのずらしを優先して動かす。壁どうしは重なってよい。解が無いときだけ「相手の円が絡む重なりは 4 割まで可」→「PC の換算だけで判定」の順に緩める（11 人制のゴール前表示は、スマホだと味方 11 人の箱だけで可動域の 7 割を占め、全員を離す解が無い）。
  - 機械検査（76 通り＝種別 × 攻守 × 人数 × 位置）：味方どうし・名前ラベル・相手の円が味方のラベルに被る重なりは両端末で 0。PC は円の重なりも 0。
- **ゴール前表示にする条件**：ボール（攻撃視点）が y70 以上のとき。58〜70 だとボールの後ろに立つキッカーとその名前が下端からはみ出すので全体表示にする。
- **ペナルティエリアの中**（攻撃視点で x20.4〜79.6・y83 超）をタップしたときは、ボールをエリアのすぐ外（y83）に置く（中は PK になるため）。
- **壁の間隔**：実寸の肩幅ではなく、画面で「並んだ壁」に見える 3.4m 相当（守備＝味方が壁のときは背番号が読めるよう 4.6m 相当）。
- **選手の割り当て**：生成した枠には、戦術ボードのスタメンを優先して、①ポジション一致 ②同じ大分類（GK/DF/MF/FW）の順で GK の枠から埋める（以前は名簿の先頭から順で、GK がキッカーになっていた）。
- **§4 ボールの軌道**：グループを開いただけでは軌道を作らない。「軌道を作る」を押したときだけ作る（自動生成は「消す」直後に再生成されて消せない・手を入れていない盤面でも確認ダイアログが出る、の 2 つを招いたため）。
- **§6 PA 拡大**：切り替え時の自動スクロールはしない（PC で最下部まで飛び、ゴール側が操作列の下に隠れたため）。
