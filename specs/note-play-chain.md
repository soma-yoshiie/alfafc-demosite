## 1. 保存（任意の項目を 3 つ足す。オーナー決定 6）

`PlayPoint` と `PlayLine` の両方に：

| 項目 | 意味 |
|---|---|
| `chain?: string` | プレーの id。同じ id の印が 1 つのプレー。無ければ単独の印 |
| `seq?: number` | プレーの中の順番（0, 1, 2…） |
| `ord?: number` | ノートの中で置いた順の通し番号（1, 2, 3…）。「1つ戻す」を時間順にするため |

- 今あるデータ（3 つとも無い）は、そのまま単独の印として読める。移行はしない。
- 新しく置く印には必ず `ord` を付ける（今のノートの最大 `ord` ＋ 1）。`chain` の id は、そのプレーの最初の印の `ord` から作る（`"c" + ord`）。
- スタッフの図（`staffDrawing`）の印にも同じ項目を付ける。
- 集計は種類（`kind`）で数えるだけなので、数え方は変わらない。ただし途中のドリブルとパスは結果を聞かず成功として残すので、成功率は今より上がりうる（オーナー決定 5 で了承）。

## 2. 関数（`lib/plays.ts` に足す。純粋な関数）

- `nextOrd(plays, lines): number`。
- `groupPlays(plays, lines): PlayGroup[]`：プレーの一覧を作る。`PlayGroup = { id, chained, steps, phase, canvas }`、`steps` は `{ type: "point" | "line", index, kind }` の並び（`index` は渡した配列の中の位置）。
  - 同じ `chain` の印を `seq` の順に並べて 1 つのプレーにする（印が 2 つ以上のときだけ `chained: true`）。
  - `chain` の無い軌道、`chain` の無いシュート、印が 1 つだけになった `chain` の軌道・シュート、「トラップミス」は、それぞれ単独のプレー（`chained: false`）。
  - 単独の「受けた」はプレーにしない（一覧に出さない。スタッツに数だけ出る）。
  - 並びは、最初の印の `ord` の順。`ord` の無い古い印は、軌道 → シュートの配列の順で、`ord` のある物より前。
- `playTitle(group, plays, lines): string`：「受けた → ドリブル → シュート（ゴール）」。最後の手の結果をかっこで付ける（シュート：ゴール／ノーゴール／コース未記録、軌道：成功／ミス）。「トラップミス」は手に入らない。
- `playNotes(group, plays, lines): string[]`：軌道の状況メモとシュートの状況メモ（空でない物）。
- `shotTarget(course): Point`：シュートの線の行き先（ピッチの座標）。y は 100（ゴールライン）、x はゴール正面図の枠（x 14〜86）をゴールの幅（7.32m）に写す：`xm = 30.34 + (course.x − 14) / 72 × 7.32`、`x = xm / 0.68`。枠の外（14 未満・86 超）は同じ式のまま（ポストの外に出る）。

## 3. ピッチの表示（`PlayAreaPitch` に足す props）

| prop | 働き |
|---|---|
| `strong?: { points: number[]; lines: number[] } \| null` | 渡した番号の印だけ濃く、ほかは不透明度 0.3。`null`・省略は全部濃い |
| `badges?: { point: number; n: number }[]` | 点の左上（左 −15px・上 −15px）に番号の丸（18px・地 `var(--accent)`・白文字 12px 700・白いフチ 1.5px） |
| `snapAt?: Point \| null` | その位置に白い輪（22px・枠 2px 白）。作図中のプレーの終わりを示す |
| `staffLayer?: { points: PlayPoint[]; lines: PlayLine[] } \| null` | スタッフの図を上に重ねる（`tone="staff"` の描き方。押せない） |

- シュートの線：`course` のあるシュートの点から `shotTarget(course)` へ、白の太い実線（太さ 0.66）＋矢じり。ノーゴール（`scored === false`）は不透明度 0.6。コースの無いシュートは線を引かない。保存はしない（点とコースから毎回描く）。`strong` で薄くなる対象には、その点の線も含める。
- 番号（オーナーに見せた §6-1 のとおり）：点（受けた・シュート）にだけ付ける（トラップミスには付けない）。軌道には付けない。番号は「選んだプレー」と「作図中のプレー」にだけ出す。数え方は、そのプレーの点を `seq` の順に 1, 2…。

## 4. 作図（`PlayRecorder`。選手もスタッフも同じ流れ）

### 4-1 続けて描く

作図中のプレー `pending = { chain, end, seq }`（終わりの位置と、次に付ける順番）を持つ。

1. 「受けた」を置く → 新しいプレー（`chain` を作り `seq 0`）。`pending` を立てる（`end` は置いた位置）。
2. 軌道（ドリブル・パス）を `pending` の無いときに描く → 新しいプレー（`seq 0`）。`pending` を立てる（`end` は軌道の終点）。
3. `pending` がある間、道具の列のすぐ下に 1 行 `.nextstep`（PDF §6 の図 C1 のとおり。行が出入りしても道具の列は動かない）：左に「続けて」（12px 灰）、右に同じ幅の 4 つのボタン「ドリブル」「パス」「シュート」「ここまで」（各 44px。「ここまで」は灰の文字）。ピッチの `snapAt` に `pending.end`。
   - 「ドリブル」「パス」：道具をその軌道にし、**次の 1 本の始点を `pending.end` に固定**する（なぞり始めの位置に関係なく、軌道の先頭に `pending.end` を足す）。描いたら同じ `chain`・`seq + 1` で足し、`pending.end` を新しい終点にする。
   - 「シュート」：`pending.end` にシュートの点を同じ `chain`・`seq + 1` で足し、コースのシート（今の `ShotCourseSheet`）を開く。プレーは終わり（`pending` を消す）。スタッフはシートが無いので点を足すだけ。
   - 「ここまで」：プレーは終わり。最後の手が軌道なら結果のシート（今の `LineResultSheet`）を開く（スタッフは開かない）。最後の手が「受けた」だけなら何も開かない。
4. 途中の軌道は結果を聞かない（`success` を入れない＝成功として数える。今の決まり）。途中で失敗したときは、そこで「ここまで」を押してシートで「ミス」を選ぶ。

### 4-2 近づけると吸い付く（C4）

`pending` がある間に、行のボタンを押さずに道具の列から置いた場合：

- 軌道のなぞり始め、またはシュートの点が、`pending.end` から画面上で 16px 以内 → 続き（4-1 の 3 と同じ。始点・位置は `pending.end` に吸い付く）。
- それより遠い、または「受けた」「トラップミス」を置いた → 前のプレーはそこで終わり（結果のシートは開かない。あとで一覧から直せる）、新しい印として置く。
- フェーズ・ピッチ番号・全面／ハーフを替えた、プレーの行を選んだ、「1つ戻す」で作図中の印が無くなった → `pending` を消す。

16px は指の太さに合わせた値（PDF §6-2 C4。実機で変えるときは定数 1 つ）。

### 4-3 プレーの一覧（選手の作図。今の「シュートの一覧」を置き換える）

- 道具・案内・「1つ戻す」の下、スタッツの上に、見出し「プレーの一覧」と、今のフェーズ×ピッチのプレーの一覧 `.playlist`（`groupPlays` の結果。1 行も無ければ見出しも出さない）。
- 行 `.playrow`：左に札（つながったプレーは「プレー 1」「プレー 2」…＝一覧の中で数える。単独は「単独」）、1 行目に `playTitle`、2 行目に `playNotes`（無ければ出さない）。
- 行を押すと選ぶ（もう一度押すと外す）。選んだプレーはピッチの上で濃く、ほかは薄く、点に番号が出る。選んだ行の下に「直す」（青の文字）と「削除」（赤の文字）（各 44px）。
  - 「直す」：最後の手がシュートならコースのシート、軌道なら結果のシート（単独のトラップミスの行には出さない。「削除」だけ）。
  - 「削除」：そのプレーの印を全部消す（印が 2 つ以上なら確認を出す）。
- 今の「シュートの一覧」（`.shotlist`。作成の画面の物）は出さない（シュートは一覧の行になる）。スタッフの作図に一覧は出さない。

### 4-4 「1つ戻す」

今のフェーズ×ピッチの印のうち、`ord` が最も大きい 1 つを消す（点と軌道をまたいで時間順）。`ord` を持つ印が 1 つも無いとき（古いノートを開いた直後）は、今と同じ（選んでいる道具の種類の最後の 1 つ）。作図中のプレーの印を消したら、`pending.end` を 1 つ前の手の終わりに戻す（無くなれば `pending` を消す）。

消した後は「1 つ前の印を置いた直後」の状態に戻す：残った中でいちばん新しい印（`ord` が最大）が、つながったプレーの途中（`chain` があり、シュートではない）なら、そのプレーを作図中に戻す（「続けて」の行が出て、続きを描き直せる）。それ以外（シュートで終わったプレー・単独の印・印なし）は作図中を消す。シートの「このシュートを削除」「この○○を削除」で印を 1 つ消したときも、同じプレーの印が残っていれば、そのプレーを作図中に戻す。

## 9. 受け入れ基準（検証 `p46/b2/`）

1. 選手・試合ノートの作成：「受けた」を置くと `.nextstep` が出る。「ドリブル」を押して離れた所からなぞっても、軌道の始点が受けた点に一致する。続けて「シュート」でコースのシートが開き、OK の後、シュートの点がドリブルの終点に一致し、ゴールへ白の太い線が出る。
2. 上の 3 つの印は同じ `chain`、`seq` が 0・1・2、`ord` が増える順。提出したノートの保存データに残る。
3. 行のボタンを使わず、ドリブルの終点から 16px 以内でシュートを置くと同じ `chain` になる。40px 離して置くと別の印になる。
4. 一覧に「プレー 1 ・ 受けた → ドリブル → シュート（ゴール）」が出る。行を押すと、その 3 つだけ濃く、番号 ①② が受けた・シュートに出る。「削除」で確認の後 3 つとも消える。
5. 「1つ戻す」が時間順（点 → 軌道 → 点の順に置いて、3 回で逆順に消える）。
6. 途中のドリブルで結果のシートが開かない。「ここまで」で開く。
7. 古いノート（`chain` なし）を編集で開いても、印の数と位置が変わらない。スタッツの数字が変わらない。
8. 詳細：プレーの一覧が出て、行を押すと濃淡が変わる。シュートで終わる行はモーダルも開く。スタッフの図があるノートで切り替えが出て、「重ねる」で青（白フチ）の線が重なる。
9. スタッフの作図でも続けて描ける（シートは開かない）。
10. スマホ 390×844 と PC 1440×1000 で横はみ出し 0、console error 0、`tsc` 0、`@media` 9。ノート以外の画面は `b1` との画素差分 0。

## 10. 実装時の判断

1. **単独の「受けた」は一覧に出さない**：数が多く、行だらけになるため。消すのは「1つ戻す」。数はスタッツに出る。単独の「トラップミス」は、はじめ同じ扱い（出さない）で実装したが、PDF の図（`n_match_pitch.png`・`n_detail_match.png`）に「単独 トラップミス」の行があるので、図に合わせて 1 行で出すように直した（数が少なく、どこで失ったかを見返す価値がある。行から 1 つだけ消せる）。
2. **作成の画面の「シュートの一覧」は、プレーの一覧に置き換えた**：同じシュートが 2 か所に出るのを避ける。詳細の「シュート」の区画（ゴール正面図）は残す。
3. **結果を聞くのは最後の 1 回**：途中の手は成功として残る。成功率が今より上がりうることはオーナーが了承済み（決定 5）。
4. **スタッフの図は、試合ノートでは選手の記録に重ねる**：`notebook-staff-redesign.md` §5 の「選手側の表示は変えない」を、この場合だけ変えた（PDF §6-3 の図とオーナー決定 12 の色）。プレーの記録が無いノートでは今のまま。
5. **作図中のプレーは chain の id だけを持ち、終わりの位置・次の順番は印から毎回求める**（実装：`PlayRecorder`）：「1つ戻す」で作図中の印を消すと `pending.end` が自然に 1 つ前の手へ戻り、印が無くなれば `pending` も消える（4-4）。フェーズ・ピッチ番号・全面／ハーフの切り替えと行の選択で id を消す。
6. **「ドリブル」「パス」の行で固定した始点は、なぞり始めが `pending.end` から 0.5（保存の座標）未満なら置き換え、それより離れていれば先頭に足す**：同じ点が 2 つ重ならないようにするため。吸い付き（C4）でも、始点は `pending.end` に置き換える。
7. **スタッフの作図の「1つ戻す」も `ord` の時間順にした**：`ord` が無い古い図は、選んでいる道具の種類の最後の 1 つ（今まで通り）。
8. **デモの新しいシュートはノーゴールにした**：試合記録（m6）の加藤の得点が 2 点（5 分・38 分）で、今ある 3 つのシュートにゴールが 2 つあるため、§8 の「シュート（ゴール）」のままだと得点が合わなくなる。数字（ゴール 2 ／ 4 本）と「2ゴール」の記述を保つ。
9. **詳細のスタッフの図の見せ方**：スタッフが見るときも切り替えは保存済みの `staffDrawing` で出る（編集中の図は下の編集用ピッチ）。「スタッフの図」だけを選ぶと選手の記録のピッチは外れ、一覧の行は残る。プレーの一覧は区画ごとに「プレー N」を数え、選んだ行は区画をまたいで 1 つだけ。
10. **作図中のプレーの番号は、点が 1 つでも出す**（§3 のとおり。受けた直後から ① が出る）。選んだ行を持ったまま新しい印を置くと、その行の選択は外れる（行の選択と作図中は同時に持たない。そうしないと新しい印が薄く描かれる）。
11. **番号の丸は、点の左上に離して置く**：丸の中心が点の中心から左 −14px・上 −14px（丸の左上の角が −23px）。§3 の「−15px」は丸の左上の角を指すと読んでいたが、点を覆うので離した。
