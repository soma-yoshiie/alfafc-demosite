# サッカーノート×試合動画 設計 v2（長尺・動画開始からの経過時間・国内サーバー）

作成：2026-09-15／設計：fable5（v1 ドラフト `specs/video-note-design-draft.md` を、ユーザーの3条件で改訂）／根拠：`specs/video-in-notebook-research.md` §8
ユーザーの条件：
1. キックオフ合わせはしない。選手は「動画の開始から何分」で場面を指す。
2. 試合予定と動画をリンクすると、1本が約90分の長尺になる（前半・後半で2本のこともある）。
3. 将来 JFA と連携し未成年の情報を扱うので、海外のサーバーは避けたい。

## 1. 結論

- **時刻は動画の経過時間だけ**を真実として持つ（`videoId` ＋ 秒）。動画が複数ある試合は動画名を前置して「後半 12:34」のように表示する。キックオフ合わせの画面は作らない（将来スタッフが任意で「前半開始」などの章を打てる余地だけ残す）。
- **1試合1本（または前後半2本）をチームで共有**する。費用は「試合数」に比例し「選手数」には比例しない。
- **動画本体は国内事業者に置く**。本命は さくらのクラウド オブジェクトストレージ（石狩／東京、ISMAP 登録）＋ さくらのウェブアクセラレータ（国内 CDN、ワンタイム URL）＋ さくらの VPS で ffmpeg 変換。100 チーム運用で **1チーム月 686 円（720p・税込）／409 円（480p）**。アプリ本体・DB・認証は東京リージョンの海外事業者でも法務上は成立するが、「動画は国内データセンターに保管」と一文で説明できることを優先する。
- **配信は変換必須**（元の 1080p のまま配信すると 20 分視聴で 1.2GB、転送費で原価が崩れる）。既定 480p、720p は明示選択。`preload="none"`、ポスター必須、「Wi-Fi のときだけ読み込む」既定オン。
- **アップロードはスタッフの PC から**（tus の再開可能アップロード）。スマホからも可能にするが「時間がかかる」旨を出す。撮影者（保護者）に依頼して PC からアップロードしてもらう導線も用意する。
- **端末内保存はしない**（iOS は 7 日無操作で IndexedDB を消しうる。90 分動画は入らない）。常にストリーミング再生。

## 2. データ構造（v1 からの変更点）

```ts
export type VideoSource =
  | { kind: "stored"; provider: "sakura"; key: string; bytes: number; playbackUrl?: string } // 国内オブジェクトストレージ＋CDN
  | { kind: "direct"; url: string; inlinePlayable: boolean }                               // mp4 直リンク（アプリ内再生できるもの）
  | { kind: "link"; url: string; site: "youtube" | "other" };                              // 参考リンク（埋め込まない・時刻対象外）

export interface VideoAsset {
  id: string; teamId: string;
  /** 「前半」「後半」「全体」「別アングル」など。試合に複数あるときは時刻表示に前置する */
  label: string;
  order: number;                          // 試合内の並び
  source: VideoSource; durationSec?: number; poster?: string;
  renditions?: { p480?: string; p720?: string }; // 変換後の再生 URL（HLS または MP4）
  status: "uploading" | "processing" | "ready" | "failed";
  matchId?: string; eventId?: string;
  appearsPlayerIds?: string[];            // 既定は MatchRecord.lineup から
  visibility: { scope: "staff" } | { scope: "team" } | { scope: "players"; playerIds: string[] };
  credit?: string; createdBy: string; createdAt: number;
  expiresAt?: number;                     // 既定 12 か月（シーズン）→ 期限後はアーカイブか削除
  removedAt?: number; removedReason?: "expired" | "deleted" | "consent";
}

/** 一点も範囲も同じ型。t は動画の経過秒。表示は「後半 12:34」（動画が1本なら「12:34」） */
export interface VideoCue { label: string; videoId: string; t: number; tEnd?: number; }

interface NoteBase {
  videoIds?: string[];
  cues?: VideoCue[];        // body 中の【後半 12:34】
  staffCues?: VideoCue[];   // staffComment 中
  frameNotes?: FrameNote[]; // 一時停止フレームの描き込み（v1 と同じ）
}

export interface VideoConsent { playerId: string; grantedAt: number; grantedBy: string; revokedAt?: number; }
```

- 本文は `<textarea>` のまま。文中に `【後半 12:34】` を挿入し、対応表を `cues` に別持ち。`cues` に無いラベルは素の文字で表示（子どもが消しても壊れない）。
- `MatchRecord.videoIds` で並び順だけ持つ。動画は独立エンティティ（練習の動画にも使える）。

## 3. 長尺ならではの設計

- **時刻入力欄**：操作バーに「12:34」と打ってジャンプできる欄を置く（長尺ではシークバーだけでは狙えない）。10 秒戻し／30 秒送り／0.5× と併用。
- **チップの挿入**：1 タップで `【後半 12:34】` を挿入し自動一時停止。既定で 1.5 秒手前。長押しで範囲（`tEnd`）。
- **25 人分のチップが 1 本に乗る**：シークバー上は 1% 幅で近接をまとめた目盛り、下に時刻順の一覧と「自分だけ／全員」「選手で絞る」フィルタ。コーチは同じ画面で全員の場面を往復できる。
- **前半・後半の 2 本**：プレイヤー上部に「前半／後半」のセグメント。チップの前置ラベルで取り違えを防ぐ。
- **ジャンプ精度**：HLS ならセグメント先頭のキーフレームに丸まる（`hls_time` 2〜4 秒、`independent_segments`）。MP4＋Range ならキーフレーム間隔（`-g 60` で 2 秒）。「12:34」に飛んで最大 2 秒ずれる前提で、チップは 1.5 秒手前を既定にする。
- **通信量**：480p（1.2Mbps）20 分視聴で約 180MB、720p（2.5Mbps）で約 375MB。初回に数字を出す。
- **オフライン**：対応しない（上記）。

## 4. 国内インフラ構成（推奨）

| 役割 | サービス | 備考 |
|---|---|---|
| 保存 | さくらのクラウド オブジェクトストレージ（石狩 or 東京） | S3 互換。基本 495 円/月（100GiB・転送 10GiB 込み）、超過 49.5 円/10GiB。1 バケット 10TiB・毎秒 100 アクセス上限 → チーム単位でバケットを分ける |
| 配信 | さくらのウェブアクセラレータ | 5 円/GiB（税込）、Range 対応、ワンタイム URL＋オリジンガードで限定公開。キャッシュ 7 日、1 ファイル 2GiB 未満 → MP4＋Range を基本、HLS はセグメント数課金に注意 |
| 変換 | さくらの VPS（4GB/4 コア 3,520 円/月・石狩）で ffmpeg | 90 分 1080p→720p が 25〜45 分（推測）。週末集中に備え 2 台（7,040 円/月）。最低利用 3 か月 |
| 代替（保存） | NTT ドコモビジネス SDPF の Wasabi（東京／大阪、契約主体は国内） | 転送無料・約 1.04 円/GB/月・最低 1,024GB/日。保存を Wasabi、配信をさくらにすると 100 チーム 350 円/チーム。ただし運営は米 Wasabi |
| 参考 | AWS 東京（S3＋CloudFront＋EC2 ffmpeg） | 100 チーム 965 円/チーム（税込）。国内事業者より約 1.4 倍 |

1 チーム単独運用の最低額：さくら 690 円/月（変換は既存アプリサーバー同居）。100 チーム：720p 68,589 円/月（686 円/チーム）、480p 40,898 円/月（409 円/チーム）。売上 1,980〜4,980 円に対する原価率は 720p で 14〜35%、480p で 8〜21%（保存・変換・配信のみ。アプリサーバー・DB・決済手数料は別）。

## 5. アップロードと変換の流れ

1. スタッフ（または依頼された保護者）が PC のブラウザで試合記録に動画を追加（ドラッグ＆ドロップ、tus で分割・再開）。スマホからも可能だが所要時間（5GB で 22〜51 分）を表示。
2. 受信後に VPS の ffmpeg が 480p／720p を生成（`-movflags +faststart`、`-g 60`）。処理中は棚に「変換中」。完了で選手に通知。
3. 元ファイルは変換後に破棄（保存費を 1/5 に）。保持期限（既定 12 か月）で本体を削除し、ノートと時刻チップは残す。
4. 自動撮影カメラ（Veo 等）は MP4 の書き出し→手動アップロードのみ想定（公開 API は確認できず）。

## 6. 法務・JFA・説明

- 「海外のサーバー」は (a) データの所在と (b) 事業者の国籍に分けて考える。AWS／Google Cloud は日本法人が契約主体で東京リージョンに置け、政府の ISMAP には AWS・GCP・Azure・Firebase・さくら・FJcloud-V が登録済み。ガバメントクラウドも AWS 中心＋さくら（2026-03 認定）。法律上は「海外事業者の東京リージョン」でも成立する。
- それでも動画本体を国内事業者に置く理由は、保護者・学校・協会への説明（「動画は国内データセンターに保管」）と、転送単価の読みやすさ。
- 契約で「クラウド例外」（事業者が個人データを取り扱わない）を成立させ、暗号化とアクセス制御を行い、プライバシーポリシーに事業者所在国・サーバ所在国・講じた措置を書く（外的環境の把握）。
- JFA：KICKOFF／JFA ID の外部連携 API は公開情報では確認できない。設計は手入力／CSV を前提にし、ISMAP 登録インフラと同意台帳で「いつでも連携審査に出せる」状態にしておく。JFA 登録サービスデスクへの照会は別途。
- 撮影ルール：県連盟レベルで「参加チーム全ての許可」「販売・譲渡禁止」が明文化されている例がある。動画追加時に「大会主催者の撮影ルールを確認した」チェックと、ダウンロード不可・チーム内限定・保持期限を規約に明記。
- 未成年：令和 8 年改正個人情報保護法（2026-07 成立、2 年以内施行）で 16 歳未満は法定代理人の同意が明文化。選手ごとの `VideoConsent` と、同意なし／撤回時のスタッフ限定への自動降格。法務レビュー必須（本書は法的助言ではない）。

## 7. 段階と工数

- **Phase 1（今のデモ・バックエンドなし）約 10 人日**：時刻チップ（挿入・パース・ジャンプ・範囲・一覧・フィルタ）、時刻入力欄、前半／後半切替、プレイヤー（sticky・キーボード時の縮小・0.5×・10 秒戻し）、スタッフの時刻コメントとフレーム描き込み。動画は mp4 直リンク（サンプル）で検証。
- **Phase 2（国内インフラ）約 20 人日**：さくら OS＋ウェブアクセラレータ（ワンタイム URL 発行の小さなサーバー）、tus アップロード（PC・スマホ）、VPS ffmpeg の変換キュー、状態通知、保持期限・削除、同意台帳。
- **Phase 3（規模対応）約 5 人日**：変換 VPS 2 台化、バケット分割、キャッシュ率の実測と 480p 既定の調整。
- 先に実機で確認すること：90 分素材の変換時間（さくら VPS）、iPhone からの 5GB tus アップロード、LINE 内ブラウザでの再生、`visualViewport` の挙動。

## 8. 未決事項

1. 「国内」の定義：資本まで国内（さくら一択）か、契約主体・データ所在が国内なら可（NTT 経由 Wasabi、AWS 東京も候補）か。
2. 既定画質（480p 推奨）と 720p の扱い（プラン差か選択か）。
3. 保持期限（12 か月）とアーカイブ（さくらアーカイブ 1TiB 3,960 円/月）の要否。
4. 動画機能をどのプランに含めるか、試合本数の上限を置くか。
5. 相手チームの子どもが映る動画の扱い（規約と同意で受容するか）。
6. スタッフが任意で「前半開始」などの章を打つ機能を残すか（キックオフ合わせの軽量版。既定はオフ）。
