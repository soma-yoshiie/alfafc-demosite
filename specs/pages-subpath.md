# 公開サイト（GitHub Pages のサブパス）で、あとから読む部品とフォントが取れるように — 正本

オーナーの依頼（2026-11-28）：「直して公開して」。前日（2026-11-27）の公開の確認で見つけた、公開サイトだけで起きる 2 件（遅い回線で初めて開くと落ちる・Web フォントが読めていない）を直す。直している途中で、同じ原因の 3 件目（セットプレーの「3D」が必ず落ちる）を見つけ、一緒に直した。

## 0. 範囲

- 触ったもの：`scripts/relativize-export.cjs`（書き出しの後処理）と、その結果の `docs/`。
- 触らないもの：アプリのコード（`app/`・`components/`・`lib/`）、`app/globals.css`、`next.config.mjs`（`basePath`・`assetPrefix` を入れない。§6 の 1）、手元（dev）の動き。

## 1. 何が起きていたか

公開サイトは `https://<ユーザー>.github.io/alfafc-demosite/`（サブパス）にある。`next build` の書き出しは、部品の場所を `/_next/…`（サイトの根から）で書く。`relativize-export.cjs` は HTML の中だけを相対パスにしていて、次の 2 か所が根からのまま残っていた。

| 残っていた場所 | 起きていたこと |
|---|---|
| webpack の実行時（`_next/static/chunks/webpack-*.js`）の公開パス `r.p="/_next/"` | ① セットプレーデザインの「3D」を押すと、必ず「Application error」になる（あとから読む部品 5 本を `https://<ホスト>/_next/…` へ取りに行き、404）。② 初めて開いたとき、ページ本体をサブパスの外へもう一度取りに行き、その 404 が本物の読み込みより先に返ると「Application error」になる（遅い回線ほど起きる。読み直すと開く） |
| CSS（`_next/static/css/*.css`）の `url(/_next/static/media/….woff2)` | ③ Web フォント（Manrope・Noto Sans JP・Bebas Neue）が読めず、代わりの書体で出る |

実測（直す前の公開サイトと、同じ中身を手元でサブパス配信したもの。どれも空のキャッシュ）：

- ①：公開サイトで「3D」→ 5 本とも 404 →「Application error」。毎回。
- ②：1.6Mbps・遅延 150ms・CPU 4 倍遅で、公開サイト 4 回中 4 回、手元の配信 18 回中 18 回。4G 相当（9Mbps・60ms）では 0 回。絞らない回線でも、2026-11-28 の確認中に公開サイトで 1 回起きた。
- ③：`document.fonts` で、読みに行った Web フォントは全部 `error`（選手のホームで 53 個）。`loaded` は代わりの書体だけ。HTML の先読み（3 本）は取れていたが、CSS が別の場所を指すので使われない。

②の仕組み：React は、ページ本体（`chunks/app/page-*.js`）と共有の部品（`chunks/980-*.js`）を webpack に「読み込んで」と頼む。webpack は「同じ `src` の `<script>` がもう HTML にあるか」を **src 属性の文字列** で探す。HTML の側は相対パス（`_next/static/…`）、webpack の側は `/_next/static/…` なので見つからず、2 本目の `<script>`（サブパスの外）を足す。その 404 が、HTML にある本物より先に返ると、読み込みの失敗として扱われる。裏づけ：直す前の版で、本物だけを 4 秒遅らせると 0.5 秒で落ちる（ページ本体でも共有の部品でも。3 回中 3 回）。本物と 2 本目を同じだけ遅らせると落ちない。

## 2. 直し方（`scripts/relativize-export.cjs`）

処理の順：加工済みでないか確かめる → HTML（前からある置換。変えていない）・実行時の公開パス（§2-1）・CSS（§2-2）の「書き換えの中身」を全部作って検査する（ここでは 1 バイトも書かない）→ まとめて書く → `.nojekyll` → `docs/` へミラー。

### 2-1. 実行時の公開パス

`_next/static/chunks/webpack-*.js` の `X.p="/_next/"` を、次の式に置き換える（`X` は圧縮後の変数名。いまは `r`）。

```js
X.p=(function(){var s="undefined"!=typeof document&&document.currentScript,a=s&&s.getAttribute("src")||"",i=a.lastIndexOf("_next/");return i<0?"/_next/":a.slice(0,i+6)})()
```

- 「この script 自身の `src` 属性の、`_next/` まで」を使う。ルートの HTML なら `_next/`、1 つ深い HTML（`404/index.html`）なら `../_next/`。
- **属性の文字列をそのまま使う**（`script.src` の絶対 URL にしない）。HTML の `<script src>` と同じ文字列になるので、webpack が「もう HTML にある `<script>`」を見つけられ、ページ本体を二重に取りに行かない（§1 の②の仕組みそのものが無くなる）。
- `document` が無い所（Worker）と、`src` に `_next/` が無い所では、元の `/_next/` のまま。

### 2-2. CSS の `url()`

`out/` の中の全部の `.css` で、`url(/_next/…` を「その CSS のあるフォルダから `_next/` まで」の相対パスに置き換える（`_next/static/css/*.css` なら `url(../../static/media/….woff2)`）。CSS の `url()` は CSS ファイルの場所から解決されるので、HTML がどの深さにあっても同じ。引用符つき（`url("/_next/…")`）も同じに扱う。

### 2-3. 止める条件（`out/` も `docs/` も書き換えずに、終了コード 1）

1. `out/index.html` に `/_next/` が 1 つも無い（もう加工済み。§2-4）。
2. `webpack-*.js` が 1 本も無い。
3. `webpack-*.js` の中の `X.p="/_next/"` が 1 か所でない。
4. CSS に、`url(/_next/…)` の形でない `/_next/` がある（`@import "/_next/…"`・`url(https://…/_next/…)` など。書き換え方を決めていない形）。
5. CSS に、`/_next/` 以外の根からの `url(/…)` がある（`url(/models/x.png)` など。サブパスでは 404 になる。相対パスで書くか、このスクリプトに書き換え方を足す）。

Next.js を上げて書き出しの形が変わったら、ここで止まる。止まったら、新しい形に合わせてこのスクリプトと仕様を直す。検査は全部「書く前」なので、2〜5 で止まった後は、スクリプトを直してそのままもう一度かけられる。

### 2-4. 2 回かけない

HTML の置換（`/_next/` → `../_next/`）は、2 回かけると `404/index.html` を壊す（`login-brand-icon.md` §5 の 5）。加工が済んだ `out/` にもう一度かけたら、何も書き換えずに止まるようにした（`npm run export` でやり直せば、`next build` が `out/` を作り直す）。

## 6. 実装時の判断・直さなかったこと

1. **`next.config.mjs` の `basePath`・`assetPrefix` を使わない**：リポジトリ名を焼き込むと、ルート配信（手元の dev・別の置き場）と両立しない。このスクリプトの前提は「どこに置いても動く」。
2. **公開パスは属性の文字列にそろえる**（§2-1）：絶対 URL にしても部品は取れるが、webpack が HTML の `<script>` を見つけられず、ページ本体（gzip で約 340KB）を 2 回取りに行く。
3. **見つからなければ止める**（§2-3）：置き換える相手が無いまま進むと、気づかずに「サブパスで落ちる版」を公開する。検査で止まれば `docs/` は前の版のまま残る。最後のミラー（`docs/` を消して写す）は前からの作りのままで、写している途中で落ちる（容量不足など）と `docs/` は半端になる。そのときは `git checkout -- docs` で戻して、やり直す。
4. **ファイル名（ハッシュ）は変えない**：`webpack-<ハッシュ>.js` と CSS は、中身を書き換えても同じ名前のまま。GitHub Pages はどのファイルも 10 分のキャッシュ（`cache-control: max-age=600`）なので、直す前の版を開いたことがある端末は、公開から 10 分のあいだ古い中身を使うことがある（そのあいだは直す前と同じ動き。新旧が混ざっても、直す前より悪くなる組み合わせは無い）。名前まで変えるには、HTML とフライトデータの参照も直す必要があり、やっていない。
5. **ページ本体の読み込みそのものが失敗したときの見え方が変わる**：HTML にある `<script>` が、webpack が見に来る前に失敗していると（回線が切れた・古い HTML が、もう無い名前の chunk を探した）、エラーの表示が出るまで最長 120 秒、起動画面のまま待つ。webpack が「読み込み中」とみなして待つためで、ルートに置いた普通の Next.js と同じ動き。直す前は、サブパスの外への 2 本目がすぐ 404 になるので、0.5 秒で「Application error」になっていた（どちらも、読み直さないと開かない）。webpack の待ち時間（120 秒）は書き換えていない。
6. **フォントを読むぶん、初めて開くときの通信が増える**：ログイン画面で 13 本・約 290KB、スタッフのホームで 31 本・約 650KB、選手のホームで 25 本・約 530KB（`font-display: swap` なので、文字は代わりの書体で先に出て、読めたら差し替わる）。1.6Mbps・CPU 4 倍遅で、使える状態になるまでが約 0.5 秒延びる（約 8.3 秒 → 約 8.8 秒。フォントを直さない版との比較）。`app/layout.tsx` の意図（フォントを自分で配る）どおりの動きで、手元（dev）と同じ。
7. **無いページ（404）は、末尾に `/` の付いた URL と 2 階層以上で、部品とフォントが取れない**：GitHub Pages はどの URL でも同じ `404.html` を返すので、相対パスでは場所を決められない。崩れないのは、末尾に `/` の無い 1 階層（`/alfafc-demosite/無いページ`）だけ。`/alfafc-demosite/無いページ/` や `/alfafc-demosite/a/b` では、404 の文字は出るが CSS とフォントが当たらない。前からで、直していない（直すには `404.html` だけサブパスを焼き込む必要があり、1 とぶつかる）。
8. **HTML は `/_next/` とアイコン 3 つだけを見ている**：`app/` に `manifest`・`opengraph-image`・`favicon.ico` などを足すと、根からの道のまま通る（止まらない）。足すときは、このスクリプトに相対化を足す。CSS は §2-3 の 4・5 で止まる。
9. **`index.txt`（RSC のペイロード）と `main-*.js`（Pages Router 用。読み込まれない）の `/_next/` は触っていない**：このアプリは 1 ルートで `<Link>` も `useRouter` も無く、どちらも読みに行かない。ルートや `<Link>` を足すときは、ここを見直す。
10. **公開パスが相対になる**ので、あとから読む部品の場所は「そのときのページの URL」から決まる。いまは 1 ルートで、`history.replaceState` も同じ道のまま（`BoardProvider.tsx`）なので問題ない。道が変わる画面遷移（`pushState` で深さが変わるもの）を足すときは見直す。
11. **`file://` で `index.html` を直接開く場合**：直す前はフォントが読めず「3D」で落ちた。直した後はフォントも「3D」の部品も読める。モデル（`.glb`）だけは、ブラウザが `file://` からの取得を止めるので読めない（前から）。
12. **確かめたブラウザ**：Chrome（headless）と、Safari と同じエンジンの WebKit（macOS の WKWebView。§5 の 9）。iPhone の実機と Firefox では確かめていない（使っているのは `document.currentScript`・`getAttribute`・相対 URL の解決で、どれも標準の動き）。
