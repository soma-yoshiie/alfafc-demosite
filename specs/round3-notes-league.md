# 予定の種類・サッカーノートへの反映・順位表の結果入力（2026-10-02・第 3 弾）

統括・設計：Fable 5.1 ／ 実装：Sonnet 5.5 ／ レビュー：Opus 5.5
前提：`specs/filter-compact-and-match-hub.md`（p14。§7）と `specs/match-records-round2.md`（p15。§10）。共通の約束（`@media` 9 本・基底と PC reset の置き場所・色はトークン・文字 12px 以上・スマホのタップ 44px・dev サーバー操作とビルドの禁止・コミットしない・`E` を新しい見出しに使わない）はそのまま。変えた箇所の注記は「p16 §n」。

## 0. 依頼（ユーザーの言葉）

1. 順位表の編集で、試合結果を入力しても順位表が完成する形にする（数値の入力とどちらか選べる）。
2. カレンダーの絞り込みの「種類」は縦に 1 列で並べる。
3. 予定を追加で種類を選ぶとき、種類ごとの色はいらない。
4. 予定を追加の「対象」（中1・中2 など）には、横に設定済みの色を置く。
5. 予定のフォームでは「カテゴリ」、絞り込みでは「種類」になっているので「種類」に統一する。
6. サッカーノートの予定別に出す予定を選べるようにする：既定は練習・試合だけ。ほかの種類は既定で出さない（編集可）。種類を新しく作るときに反映するか選べる。予定を作るときにも選べる（同じ種類でも、ミーティングはノートを書いてほしい、など）。

{categories.map((c) => {

## §2 予定フォームの種類の選択から色を外す

予定フォーム（`type: "event"`）の種類のチップ（`button.evcatchip`）：

- 色の点（インライン style の 9px の丸）を消す。選択中のインライン style（`borderColor`／`color` に種類の色）も消す。
- 選択中の見た目は CSS で：`.evcatchip.on` を `--accent` の枠と文字・`--accent-tint` の地にする（`.grouppick-item.on` と同じ値。既存の `.evcatchip.on` のルールを確かめ、種類の色に頼っている部分だけ直す）。
- 種類の色そのもの（`EventCategory.color`、種類の管理の色の選択、予定の詳細・一覧のタグの色）は今回は変えない。

## §5 サッカーノートに反映する予定

### 5-1 データ

- `EventCategory.noteTarget?: boolean`：この種類の予定をサッカーノートの対象にするか。未定義のときの既定は **組込み（練習・試合）＝ true、それ以外＝ false**。
- `TeamEvent.noteTarget?: boolean`：予定ごとの上書き。未定義＝種類に従う。
- `lib/calendarUtils.ts`：

```ts
/** 種類の既定（未定義なら 組込み＝true／それ以外＝false） */
export const categoryNoteTarget = (c: EventCategory): boolean => c.noteTarget ?? c.builtin === true;
/** 予定がサッカーノートの対象か（予定の上書き → 種類の設定） */
export function eventNoteTarget(e: TeamEvent, cats: EventCategory[]): boolean {
  return e.noteTarget ?? categoryNoteTarget(categoryOf(e, cats));
}
```

  `categoryOf` は種類が見つからないと組込み（kind）へ落ちるので、種類を消した予定は練習・試合の扱いになる。
- `TeamProvider`：
  - `categories` の実効値（組込みへ保存済みの上書きをマージしている useMemo）で、組込みの上書きに `noteTarget` も含める（今は `color` だけ）。
  - `addCategory(label, color, noteTarget?: boolean)`：第 3 引数を足す（未指定は false を保存しない＝未定義のまま）。
  - `updateCategory(c)`：組込みの分岐でも `noteTarget` を保存する（今は `{ id, label, color }` だけ）。
- `lib/storage.ts` の `loadTeam()`：種類・予定の `noteTarget` が boolean でなければ落とす。
- 繰り返し予定：シリーズの各回にも `noteTarget` を引き継ぐ（`addEventWithRecurrence`・`updateSeriesFollowing`・`updateEventOnly` で、予定フォームのほかの項目（title・place など）と同じ経路に乗せる。シリーズのひな形に項目を列挙している箇所があれば足す）。
- 試合記録から自動で作る予定（`fromMatch`）は kind が match なので既定で対象（変更なし）。

### 5-2 種類の管理シート

- 各行（組込みの練習・試合も）に、名前の下の補足として「サッカーノート：反映する／反映しない」を出す。
- 行の編集（今の色・名前の編集と同じ場所）に丸トグル「サッカーノートに反映する」を足す。組込みは名前は変えられないが、色とこのトグルは変えられる。
- 「新しい種類を追加」にも同じトグル（既定はオフ）。追加時に `addCategory(label, color, noteTarget)` へ渡す。
- トグルの部品は既存の `.daytoggle`（`label.daytoggle > input[type=checkbox] + span`。体力測定の種目管理の「小さい方が良い」と同じ）を使う。

### 5-3 予定フォーム

- 「種類」の欄のすぐ下に丸トグル「サッカーノートに反映する」（`.daytoggle`）。補足 `.fieldhint`：「オンにすると、サッカーノートの予定別に出ます」。
- 初期値：編集＝`eventNoteTarget(予定, 種類)`、新規＝選んでいる種類の既定。
- 種類を切り替えたとき：利用者がまだトグルを触っていなければ、新しい種類の既定に合わせる。触った後は変えない。
- 保存：トグルの値が「選んでいる種類の既定」と同じなら `noteTarget: undefined`、違えば boolean を入れる。
- 種類の管理シートへ行って戻っても入力が消えないこと（今の from/date の引き継ぎと同じ扱い。フォームが作り直される場合は、トグルも他の項目と同じ扱いでよい）。

### 5-4 サッカーノート側（components/NotebookScreen.tsx）

- 予定別の一覧（`NoteList` の `events`。スタッフ・選手とも）：`eventNoteTarget(e, team.categories)` が true の予定だけにする。**30 件に切る前に**絞る（対象外の予定で 30 件が埋まらないように）。種類の実効値は `useTeam().categories`。
- 作成シートの並び替え（`todayEventKinds`）：今日の予定のうち対象の予定だけを見る。
- ほかにサッカーノートが予定を数える・並べる箇所（提出／未提出の集計、未提出の催促、通知など）があれば同じ条件にそろえる。カレンダーの日別パネル（その日の予定の一覧。情報の表示）は変えない。
- 対象外の予定の日に書かれたノート：予定別では「予定に紐づかないノート」の側に出る（今の作りのまま。消えないこと）。

### 5-5 予定の詳細

- スタッフに見える 1 行を足す：日時・場所の `.dsec` の中の最後に `.dline`「サッカーノート：反映する」／「サッカーノート：反映しない」。選手・保護者には出さない。

## §6 順位表：試合結果からも作れる

### 6-1 データ（lib/types.ts・lib/sampleLeague.ts・lib/storage.ts）

```ts
/** リーグ内の 1 試合（p16 §6）。チームは LeagueRow.id で指す */
export interface LeagueResult {
  id: string;
  aId: string;
  bId: string;
  aScore: number;
  bScore: number;
  /** YYYY-MM-DD（任意） */
  date?: string;
  /** 取り込み元の試合記録（自チームの記録から取り込んだとき）。同じ記録を二重に取り込まないために持つ */
  matchId?: string;
}
// LeagueTable に足す
/** 入力の方法。未定義＝"manual"（数値を直接入力） */
mode?: "manual" | "results";
/** mode==="results" のときの試合結果 */
results?: LeagueResult[];
```

- `lib/sampleLeague.ts`：`rowsFromResults(rows: LeagueRow[], results: LeagueResult[]): LeagueRow[]` — 各チームの 勝・分・敗・得点・失点 を結果から数え直した行を返す（id・name・own はそのまま。存在しないチーム id を指す結果は無視）。
- **保存の形**：`mode === "results"` で保存するとき、`rows` には `rowsFromResults` の結果（数え直した数値）を入れ、`results` も一緒に保存する。こうすると表示側（`computeStandings`・ホームのタイル・簡易表・閲覧シート）は今のまま変えなくてよい。
- `TeamProvider.setLeague` の引数を `{ title?, rows, mode?, results? }` に広げる。
- `loadTeam()` の正規化：`mode` は `"manual" | "results"` 以外なら落とす。`results` は配列でなければ落とす。各結果は id・aId・bId が文字列、スコアは 0 以上の整数（NaN は 0）、`aId === bId` や存在しないチームを指すものは落とす。

### 6-2 編集シート（`type: "league"`）

```
h2「順位表を編集」
[名称]
[入力の方法]  .toolseg（.tseg 2 つ）：「数値を入力」｜「試合結果を入力」
── 数値を入力（今のまま）──
  チームごとのカード（チーム名＋勝・分・敗・得点・失点）／＋ チームを追加
── 試合結果を入力 ──
  見出し「チーム」
    チーム名だけのカード（.lgedit-row。自チームは名前＋「自チーム」タグ、ほかは名前の input と削除）。
    名前の右に、結果から数えた「勝-分-敗」を小さく出す（.lgedit-sum。読み取り専用）
    ＋ チームを追加
  見出し「試合結果」（N 件）
    1 試合 1 枚のカード（.lgres-row）：[チーム A の select] [点] - [点] [チーム B の select] [日付（任意）] [削除]
    ＋ 試合結果を追加（空の 1 行。チーム A は自チーム、B は未選択で始める）
    スタッフ向けの補助：「試合記録から取り込む」ボタン（button.dynadd）
注記 .evnote
  数値：今の文言のまま
  結果：「入力した試合結果から、勝・分・敗・得点・失点を数えて順位表を作ります。順位は 勝点（勝 3・分 1）→ 得失点差 → 得点 の順です。」
button.bigbtn「保存する」
```

- 方法の切り替え：
  - 開いたときは保存済みの `mode`（未定義は「数値を入力」）。
  - 「数値 → 結果」へ切り替えたとき、注記の上に 1 行の注意 `.lgedit-warn`：「保存すると、順位表の数値は試合結果から数え直した値に置き換わります。」（結果が 0 件のうちは「試合結果を 1 件以上入れると順位表が作られます。」）。
  - 「結果 → 数値」へ切り替えたとき：数値の欄には、その時点の結果から数えた値を入れる（結果の入力を引き継いで手直しできる）。入力済みの結果は下書きに残す（保存すると `mode: "manual"` になり `results` は保存しない＝消える。切り替えただけでは消えない）。
- 「試合記録から取り込む」：
  - 自チームの試合記録（`team.team.matches`）のうち、**相手名がチーム一覧の名前と一致**（前後の空白を除いて完全一致）し、まだ取り込んでいない（同じ `matchId` の結果が無い）ものを、自チーム＝A・相手＝B・スコア・日付・`matchId` で結果に足す。
  - ボタンの上に大会の select（「すべての大会」＋登録済みの大会。既定は「すべての大会」）を置き、選んだ大会の記録だけを対象にする。
  - 押した後に toast：「N 件を取り込みました」。取り込めなかった記録があれば「（相手がチーム一覧に無い M 件は取り込めません）」を続ける。0 件なら「取り込める試合記録がありません」。
- 検証（保存時）：
  - チーム名が空 → 今の文言。
  - 結果の行で、チームが未選択・A と B が同じ → toast「試合結果のチームを選んでください（同じチームどうしは入力できません）」。
  - スコアは空欄＝0、0 以上の整数（全角数字も可。今の数値欄と同じ扱い）。それ以外は今の文言。
- チームの削除：そのチームを含む結果があるときは `window.confirm("このチームの試合結果（N 件）も削除されます。よろしいですか？")`。OK なら結果も消す。
- スマホ 390px で横はみ出しなし：結果のカードは 1 段目に「A の select — B の select」、2 段目に「点 - 点・日付・削除」のように折り返してよい。select と input は `.formfield` の入力と同じ見た目（既存クラスの流用）。
- CSS（基底）：`.lgedit-warn`（`--warn` の文字・12px）、`.lgedit-sum`（`--mut`・12px・nowrap）、`.lgres-row`（`.lgedit-row` と同じ器）、`.lgres-teams`（grid 2 列・gap 6px）、`.lgres-score`（flex・gap 6px・align center。点の input は幅 56px・中央寄せ）。PC reset は `.lgres-row` を `--r-md` に。

### 6-3 閲覧

- 順位表の表示（PC の右ペイン・スマホの閲覧シート・ホーム）は変えない。
- 閲覧シート（`leagueView`）と PC の右ペインの「最終更新」の横に、`mode === "results"` のとき「試合結果 N 件から作成」を小さく足す（`.phubupd` と同じ見た目。クラスは流用）。

## §7 受け入れ基準

1. `npx tsc --noEmit` が通る。`grep -c "^@media" app/globals.css` が 9。
2. カレンダーの絞り込みの種類が、PC・スマホとも 1 行に 1 つずつ縦に並ぶ。
3. 予定フォームの種類のチップに色の点が無く、選択中は青（`--accent`）。対象のチップ（全員以外）に色の点がある。試合記録フォームの対象にも点がある。
4. 利用者に見える「カテゴリ」が「種類」になっている。
5. 既定で、サッカーノートの予定別に出るのは練習・試合の予定だけ（保護者会・遠征合宿は出ない）。種類の管理で「反映する」にすると出る。予定フォームのトグルで予定ごとに上書きできる。
6. 順位表の編集で「試合結果を入力」に切り替え、結果を入れて保存すると、その結果どおりの順位表になる。再読み込み後も残る。「数値を入力」に戻して手直しもできる。試合記録から取り込める。
7. ほかの画面（ホーム・戦術ボード・チャット・設定など）に差分が無い。

## §8 実装時の判断（2026-10-02。以後はここが正）

実画面の確認（受け入れ 37 項目・レビュー修正 9 項目・前回までの 126 項目、ほかの画面は時刻表示以外に差分なし）と、Opus 5.5 のレビュー（3 観点。指摘 16 件のうち反証を通過した 12 件＝重複を除いて 8 件、すべて軽微）を受けて、統括が次のとおり決めた。

**種類の色**

- 外したのは予定フォームの種類のチップの色だけ（選択中は青）。種類の管理の色の選択、予定の詳細・一覧のタグの色、スマホの種類の点は残してある（依頼は「予定を追加で種類を選ぶ際の色」。ほかも外すかはユーザーの判断待ち）。

**サッカーノートへの反映**

- 予定別の行の種類の表示は、ノートの種別（練習／試合）ではなく予定の種類の名前（`categoryOf(...).label`）にした。保護者会・ミーティングを反映したとき「練習」と出るのを避けるため。長い名前は省略（`max-width: 8em`）。
- 対象の予定が 0 件で、カレンダーには今日までの予定があるときは「サッカーノートに反映する予定がありません。種類の管理や予定のフォームで変えられます。」を出す。
- 種類を消したとき、その種類が「反映しない」だった予定には `noteTarget: false` を残す（消した途端に予定別へ並び始めないように。設計書 §5-1 の「組込みへ落ちる」からの変更）。
- 予定を開いて保存し直したとき、トグルの値が種類の既定と同じなら上書きは消える（＝以後は種類の設定に従う）。設計どおり。
- サッカーノートのホームの日別パネル（その日の予定の一覧）は絞らない。
- 今回足したトグル（予定フォーム・種類の管理の編集と追加）は `label.daytoggle.notetoggle`。スマホでも ON は青・高さ 44px（基底の `.daytoggle` は緑のまま。「終日」などは変えていない）。
- 繰り返し予定は、フォームの値がオブジェクト展開で各回へ渡るので追加の対応なしで引き継がれる。

**対象の色の点**

- 点と文字の間は `.grouppick-item` の gap（6px）に任せる（`.grouppick-dot` に margin は付けない）。試合記録フォームの対象にも点を出した。

**順位表の結果入力**

- 結果が 0 件のまま「試合結果を入力」で保存しようとしたら止める（toast「試合結果を 1 件以上入れてください」）。切り替えて見ただけで手入力の数値が全部 0 になるのを防ぐ。
- 「結果 → 数値」へ切り替えたとき、有効な結果が 0 件なら数値の欄は書き換えない。
- 結果の行は常に 2 段（1 段目＝2 つのチーム、2 段目＝点・日付・削除）。
