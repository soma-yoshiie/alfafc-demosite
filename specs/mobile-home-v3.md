# スマホ版ホーム v3 仕様（移動メニューをやめ、PCと同じスタッツ中心の見た目にする）

作成：2026-09-14／設計：fable5／実装：sonnet5／レビュー：opus5
前提：v1（`specs/mobile-redesign.md`）・v2（`specs/mobile-redesign-v2.md`）の上に積む差分仕様。CSSの約束（`@media` 9本、PCブロックは「mobile-redesign PC reset」セクション以外触らない、スマホ限定は `.mhead` の有無や専用コンテナで判定）はそのまま。
対象：幅1024px未満のホーム画面（スタッフ／選手・保護者）。PC（≥1024px）のDOM・見た目・挙動は変えない。

## 0. ユーザー指示（原文の要点）

1. ホームにあるコーチング／チーム／その他などの行メニューは、下部タブから行けるので重複していて良くない。ホームからその項目を無くす。
2. ホームはPC版と同じように、いろいろなスタッツが表示される見た目重視にする。
3. PC版と同様に、次の試合予定などが色つきでカッコよく表示されるようにする。

## 1. 方針

- PCのスタッフ用ホーム（`HomeMenu.tsx` の `MatchdayBoard`）を**単一カラムに組み替えたもの**をスマホのホームにする。区画は上から「あいさつ」「次の予定（ヒーロー）」「指標タイル＋推移グラフ」「今月のトピック」「最新の動き」「今月のハイライト」「フッター」。
- 色：PCのホームと同じ配色を使う（ヒーローの濃紺グラデーション＋白文字、指標タイルの青／緑／橙／紫のアクセント、トピックのバー色）。v1 §8 のグラデーション・紫の禁止は、**PCと同じ既存デザインを再現するこの画面に限って例外**とする（新しい色は足さない。PCの `.mdb-*` / `.kpitile` の実際の描画値をそのまま写す）。
- 行メニュー（`MenuGroup`/`MenuRow`）、「今日やること」カード、「チームのいま」4タイルはホームから削除する（`MobileRows.tsx` はコーチングハブ・その他で使うので残す）。
- ロジックは `MatchdayBoard` と同じ集計を使う（同じ数字がPCとスマホで出る）。集計・ヘルパー（`opponentFromTitle` `categoryLabel` `relTime` `hashIdx` `rankTop3` `goalsMap` `assistsMap` `attendancePctMap` `useCountUp` `useCountdown` `fmtDelta` `trendDelta` `MdbChart` `MdbRing` `PULSE_METRICS` `TOPIC_LABELS` `TOPIC_UNITS` `LEAGUE_MINI_ROWS` など）は `HomeMenu.tsx` から `export` するか、`useMatchdayData` のようなフックに切り出して両方から使う。**PCの `MatchdayBoard` の描画結果は変えない**（PCスクリーンショット差分で確認）。

## 2. スタッフのホーム（スマホ）

上から：

1. **ヘッダー**（現状維持）：エンブレム＋クラブ名＋プラン名、右に設定（歯車）。
2. **あいさつ**：日付／「こんにちは、〇〇さん」＋役割ピル（現状維持）。右に**ベル**（`対応が必要なこと`。PCの `mdb-bell` と同じ件数＝次の予定の未回答＋未コメント）。タップで直下に「対応が必要なこと」の行（PCの `bellRows` と同じ内容：出欠が未回答 n名 → チームのカレンダーの該当予定、未コメントのノート n件 → ノート）を開閉する（パネルではなくインライン展開）。0件ならベルにバッジを出さない。
3. **ヒーロー（次の予定）**：`.mh-hero`。PCの `.mdb-hero` の描画と同じ濃紺グラデーション地・白文字・角丸 `--r-lg`。
   - 試合で対戦相手が取れるとき：エンブレム＋自チーム名「VS」相手名（PCの `mdb-vscard` を縦幅に収まる大きさで）。それ以外：予定タイトル（20px 700）＋種別ピル。
   - カウントダウン（`useCountdown`。「まもなく開始」または「n日 n時間 n分」）を白地の丸ピルで。
   - メタ：会場／開始／メモ（あれば）／出欠 未回答n名 を**2列**のグリッドで（ラベル 11px 薄い白、値 14px 700 白）。
   - 主操作「出欠を確認」（白地・濃紺文字、高さ44px、全幅）→ `board.setTeamIntent({ tab: "cal", eventId })` ＋ `setScreen("team")`。
   - 次の予定が無いとき：白カード「次の予定はまだありません」＋「予定を追加 ›」（チームのカレンダーへ）。
4. **指標タイル 2×2**（`.mh-kpis`）：今週の提出（青）／出席率（緑・リング付き）／勝率（橙）／リーグ順位（紫）。PCの `kpitile` と同じ値・同じ前週比／前月比の表示（`mdb-kpidelta`）。タイルは白地＋1px `--outline`、左端3pxのアクセント色（PCと同じ色）、数値 24px 700 アクセント色、ラベル 12px `--mut`。タップで下のグラフの指標が切り替わる（選択中のタイルはアクセントの薄い地）。**自動切替はしない**（チェックボックスも出さない）。
5. **推移グラフ**（`.mh-chart`）：白カード、見出し（PCと同じ `chartTitle`）、`MdbChart`（`.mdb-chart*` クラスをそのまま使い、スマホ用の基底ルールを `.mhome-root .mdb-chartwrap …` の形でPCの値を写して足す）。リーグ順位のときは簡易順位表（`ptable`）。
6. **今月のトピック**（`.mh-topic`）：白カード、見出し＋「◯◯ランキング」、上位3人の横バー（PCと同じ3色）＋値。データが無ければ「まだデータがありません」。
7. **最新の動き**（`.mh-feed`）：白カード、上位4件（自動スクロールはしない）。イニシャルの丸（PCと同じ5色）＋本文＋相対時刻。
8. **今月のハイライト**：チップ（PCと同じ3種）。無ければ出さない。
9. **フッター**：小さく「ALFA FOOTBALL」＋ログアウト（現状維持）。

## 3. 選手・保護者のホーム（スマホ）

上から：ヘッダー／あいさつ／ヒーロー（次の予定。メタは 会場／開始／メモ／自分の出欠（回答済み：出席・未定・欠席／未回答）、主操作は「出欠を回答する」→ チームのカレンダーの該当予定）／指標タイル 2×2（今週のノート（自分）・連続記録（サッカーノートの「n週連続で記録中」と同じ算出。無ければ「これまでの合計」）・達成度（週平均。サッカーノートのホームと同じ算出）・チーム勝率）／直近の試合（`matchcard` 相当：勝／分／敗＋相手＋スコア。試合記録が非公開なら出さない）／最新の動き（チーム全体の feed から4件）／フッター。
- 行メニュー（サッカーノート／チーム／チャット／セットプレーデザイン）と「今日・練習」「今日のノート」タイルは削除する。セットプレーデザインは「その他」タブから開ける（v2 で対応済み）。
- 集計はサッカーノート側（`NotebookScreen.tsx` / `NotebookTools.tsx` / `lib/*`）の既存関数を再利用する。既存関数が無く新規集計が必要な指標は省略してよい（省略した指標は報告に書く）。

## 4. 部品・寸法（v1 §8 に従う。例外は §1 の配色のみ）

- 画面左右 16px、カード間 12px、区画間 24px。カードは白地＋1px `--outline`、角丸 `--r-lg`、影なし。ヒーローだけ濃紺地。
- 文字：見出し 15px 700、本文 14px、補助 12px、数値は `tabular-nums`。
- タップ領域 44px 以上（ベル、タイル、出欠ボタン、ログアウト）。
- アイコンは `icons.tsx` の線画。絵文字は使わない。
- 新しい hex 色を追加しない（PCの既存値・トークンを使う）。
- CSS は基底に `.mhome-root`（スマホホーム専用の外枠）配下の新規ルールとして書く。PC には `.mhome-root` が存在しないので PC reset は不要。既存の `.mhome-*`／`.mstat*`／`.mrow`（ホームで使わなくなった分）のうち他画面で未使用のものは削除する（`.mrow` 系は残す）。

## 5. 変えないもの

- PC（≥1024px）の `MatchdayBoard`・選手PCホームのDOM・見た目・挙動。
- 下部タブ、コーチングハブ、その他、チーム、ノート、コーチラボ、設定の各画面。
- 保存キー・集計ロジック。

## 6. 実装分割

- **Phase A（実装）**：§2・§3 のスマホホームを `components/MobileHome.tsx`（新設）として実装し、`HomeMenu.tsx` のスマホ分岐から呼ぶ。集計の共有（§1）。CSS（§4）。`npx tsc --noEmit`、`@media` 9本。`node scratchpad/tools/mobile_audit.js a1` で全画面撮影（ホーム2枚＝上部／末尾、選手ホーム）と `node pc_baseline.js pc_a1`＋`compare.py diff` でPC不変。
- **Phase C（レビュー）**：opus5 ×3 並列（目視：PCホームとの見た目の整合・v1 §8・文字切れ／コード差分：PC不変・集計共有・hydration・a11y／PC差分＋実測：タップ領域・はみ出し・数値の一致）。
- **Phase D（修正）**：致命・要修正の反映と最終検証（最大2周）。

## 7. 検証手段（`scratchpad/tools/`）

- `node mobile_audit.js <outdir>`（`c_home` `c_home_bottom` `p_home` を含む全画面）、`node pc_baseline.js <outdir>`＋`python3 compare.py diff pc_base <outdir> <diffdir>`（日時・カウントダウン・最新の動き・グラフの動的差分は許容）、`python3 compare.py sheet`／`pair`。
- 変更前のスマホ：`scratchpad/tools/v2f/`（`c_home.png` `c_home_bottom.png` `p_home.png`）。PC基準：`scratchpad/tools/pc_base/ホーム.png`（見た目の参照にも使う）。
- 数値の一致：PCの `MatchdayBoard` の表示値（今週の提出／出席率／勝率／順位／トピック／最新の動き）とスマホの表示値が同じであること（puppeteer で両方の DOM から読んで比較）。

## 8. 受け入れ基準

1. スマホのホームに行メニュー（コーチング／チーム／その他の行、選手のサッカーノート／チーム／チャット／セットプレー行）と「今日やること」「チームのいま」が無い。
2. 次の予定がPCと同じ濃紺のヒーローで表示され、試合なら「VS 相手」、カウントダウン、会場／開始／出欠、主操作ボタンがある。
3. 指標タイル4つ・推移グラフ・今月のトピック・最新の動きがあり、値がPCと一致する。タイルのタップでグラフが切り替わる。
4. 選手のホームも §3 の構成になっている。
5. 横はみ出しゼロ、文字切れ・重なりなし、タップ領域44px以上。`tsc` 成功。`@media` 9本。PC10画面が変更前と一致（動的差分を除く）。
6. v1 §8 に新たな違反が無い（§1 の配色例外を除く）。
