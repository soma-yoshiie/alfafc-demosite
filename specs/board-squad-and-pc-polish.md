4. 戦術ボード：学年（グループ）をタップしたとき、控えと登録選手の表示（人数）も変わるようにする。
5. PC：「中1」「中2」…を選ぶボタンが丸く、UI として浮いている。四角くする。ほかにも同じような場所があれば直す。
6. （再掲）カレンダーの場所の履歴 → `specs/groups-editing-and-place-history.md` §6 で実装済み。今回は動作の再確認だけ行う。

## 1. PC の「‹ ホーム」を外す

- 対象：PC（`usePc()`／`min-width:1024px`）のヘッダーにある「‹ ホーム」（`.fpback`）。`ConsoleScreens.tsx`（ライブラリ・設定ほか 2 箇所）、`ChatScreen.tsx`、`DrillEditor.tsx`、`TeamHub.tsx`、`NotebookScreen.tsx`、コーチラボの画面、および戦術ボード／セットプレーデザイン右上のアイコン列にあるホームのアイコン（同じ理由で不要）。
- **押した先がホームのときだけ** 外す。画面内の戻る（例：サッカーノートで詳細・検索から一覧へ戻る「‹ 戻る」、チーム運営のペインの「‹ 戻る」）は残す。
- 外したあと、画面名（`.brand .logo`）の左端を戦術ボードの画面名と同じ位置（PC で x=226 前後）に揃える。`marginLeft: 4` などの帳尻合わせは不要になれば消す。
- スマホは変えない（スマホは `MobileHeader`）。

## 2. 戦術ボード：スタメン／ベンチ／メンバー外

### 2-1. データ（`lib/types.ts` の `BoardState`）

```ts
/** ベンチ入りの選手 id（並び順＝表示順）。スタメン（slots の pid）とは重ならない */
benchIds?: string[];
/** ベンチの枠数。未定義＝7 */
benchSize?: number;
```

- スタメンでもベンチでもない選手が **メンバー外**。
- 旧データ（`benchIds` 未定義）は読み込み時に 1 度だけ補う：スタメン以外の選手を名簿順に先頭から `benchSize`（7）人ベンチに入れる。初回シード（`makeInitial`）も同じ規則。
- `benchSize` は 0〜20。ヘルパー `lib/squad.ts`：`benchOf(state)`、`outsideOf(state)`（メンバー外）、`normalizeSquad(state)`（重複・存在しない id・スタメンとの重複・枠超過を直す。reducer の各アクションの最後に通す）。
- reducer（`BoardProvider.tsx`）：
  - `SET_BENCH_SIZE { size }`：縮めて人数が枠を超えたら、ベンチの末尾からメンバー外へ。
  - `BENCH_ADD { pid }`：枠が満杯なら何もしない（UI 側で toast「ベンチが満員です（7/7）。枠を増やすか、誰かを外してください」）。`BENCH_REMOVE { pid }`。
  - `ASSIGN`／`ASSIGN_MANY`：枠に入った選手はベンチから外す。
  - `REMOVE`（枠から外す）：外れた選手はベンチに空きがあればベンチの末尾へ、無ければメンバー外へ。`UNASSIGN_MANY` も同じ。
  - ベンチ／メンバー外 → ピッチへのドラッグ交代（既存の `Bench.tsx` の処理）：入る選手がベンチに居た場合、出る選手はその位置に入る。メンバー外から入った場合、出る選手はベンチに空きがあればベンチ末尾、無ければメンバー外。
  - 選手の削除・名簿の同期（`SYNC_ROSTER`）で存在しない id は消す。セットプレー用の第 2 文書（`spState`）は対象外（ベンチの概念を持たせない）。
  - API：`setBenchSize(n)`／`benchAdd(pid)`／`benchRemove(pid)` を context の公開箇所すべてに足す。
- ライブラリ保存（`SavedPlay`）の形式は変えない（保存された戦術を開いてもベンチは現在のまま）。

### 2-2. 右カラムの数字（`StatBar.tsx`）

- 「スタメン 11/11」のタイルを **外す**。
- タイルは 3 つ：**ベンチ**（`n/枠数`）／**メンバー外**（`n人`）／**登録選手**（`n人`）。
- グループ絞り込み（key `"board"`）で学年などを選んでいるときは、**3 つともそのグループの人数**にする（ベンチ＝そのグループのベンチ入り人数「3人」、メンバー外＝そのグループのメンバー外人数、登録選手＝そのグループの人数）。タイルの上に小さく「中3 の人数」（12px `--mut`）。「すべて」に戻すと全体の数と `n/枠数` に戻る。

### 2-3. ベンチ（`Bench.tsx`）

- 見出し行：「ベンチ」＋人数「5/7」＋ **枠数のステッパー**（`−` `7` `＋`。ボタンは PC 28px／スマホ 44px のタップ領域、`aria-label`「ベンチの枠を減らす／増やす」）。右の説明文は既存のまま。
- グループのチップ（既存）→ ベンチのカード → 見出し **「メンバー外 52人」** → メンバー外のカード。チップの絞り込みは両方に効く。
- メンバー外が 12 人を超えるときは既定で折りたたみ（見出しをタップで開閉、`aria-expanded`）。開閉の状態は `sessionStorage` で保持。
- カードの右上に小さな操作ボタン：ベンチのカードは「−」（メンバー外へ。`aria-label`「メンバー外にする」）、メンバー外のカードは「＋」（ベンチへ。`aria-label`「ベンチに入れる」）。カード本体のタップ（選手の詳細を開く）とドラッグ交代は既存のまま。操作ボタンのタップでドラッグやカードのタップが発火しないこと。
- メンバー外のカードはベンチのカードと同じ文法で、背景だけ 1 段沈める（`--surface-low`）。
- 0 件の文言：ベンチ「ベンチ入りの選手はいません。メンバー外の選手の ＋ で追加できます。」、メンバー外（絞り込みで 0）「このグループのメンバー外の選手はいません。」
- 「選手を配置」シート（`AssignBody`）の一覧は、ベンチの選手を先・メンバー外を後に並べ、ベンチの選手の行に小さく「ベンチ」のバッジ（既存の並び＝役割の一致優先はその中で維持）。

### 2-4. 試合予定にメンバーを登録（`Bench.tsx`・`SheetManager.tsx`）

- ベンチの見出しの下（スタッフのみ）に枠線ボタン **「試合予定にメンバーを登録」**。押すとシート（新しい `SheetType` `"squadToEvent"`。PC は通常の中央ダイアログ）：今日以降の「試合」の予定を日付順に最大 10 件（日付・タイトル・対象グループのバッジ・登録済みなら「登録済み」）。タップで §3 の `squad` を保存し、toast「9/19 練習試合 vs 青空FC にメンバーを登録しました」。試合の予定が無ければ「今日以降の試合の予定がありません。カレンダーで試合の予定を作ってください。」
- スタメンが 1 人も居ないときは登録できない（toast）。

## 3. カレンダー：試合のメンバー（`lib/types.ts`・`TeamProvider.tsx`・`TeamHub.tsx`）

```ts
export interface EventSquad {
  formation: string;
  starters: { role: string; playerId: string }[]; // slots の順（空き枠は入れない）
  bench: string[];                                  // benchIds の順
  updatedAt: number;
}
export interface TeamEvent { /* 既存… */ squad?: EventSquad }
```

- `TeamProvider`：`setEventSquad(eventId, squad | null)`。`lib/storage.ts` の正規化：形が壊れていれば `undefined`。選手の削除時に `squad` からもその id を外す（スタメン・ベンチとも）。
- 予定の詳細（`eventView`）：種別が試合の予定に **「メンバー」** の欄。
  - 登録あり：フォーメーション、スタメン（役割＋背番号＋名前。GK→DF→MF→FW の順）、ベンチ（背番号＋名前）。最終更新の日時（12px `--mut`）。
  - スタッフ：「戦術ボードのメンバーで更新」（枠線）と「メンバーを消す」（確認あり）。登録なしのときは「戦術ボードのメンバーを登録」＋説明 1 行。戦術ボードにスタメンが居なければ toast。
  - 選手・保護者：登録があれば同じ一覧を閲覧のみで表示し、先頭に自分の立場を 1 行：「あなたはスタメンです（CM）」「あなたはベンチです」「あなたは今回メンバー外です」（自分の行は `--accent` 文字）。登録なしなら欄ごと出さない。
- 予定カード（カレンダーのリスト・日別シート・ホームの次の予定）：`squad` がある試合に小さなバッジ「メンバー発表」（`.evgroups` の文法・`--accent-tint`）。
- 試合記録フォームへの引き継ぎはしない（試合記録のスタメン枠は 8 人制の別体系）。

## 4. PC：丸い操作ボタンを四角に

- PC だけ（2 つ目の PC ブロック末尾の `/* === mobile-redesign PC reset === */` に追記）。角丸は `var(--r-md)`（8px）。分割ボタンの内側は `var(--r-sm)`（6px）。
- 対象（PC 全画面を機械的に洗い出した結果）：
  - `.grouppick-item`（学年・グループのチップ。戦術ボード・サッカーノート・試合記録・名簿・チャット・予定フォーム・配信・連絡・選手フォーム・試合記録フォーム・送信先）
  - `.chip`（サッカーノート提出の種別、セットプレーデザインの種別 CK/FK…）
  - `.catchip`（コーチラボのカテゴリ）
  - `.dxstepadd`（練習メニューの「＋ 場面」）
  - `.kpireport`（ダッシュボードの「レポート」）
  - `.searchbar`（サッカーノートの検索）
  - `.toolseg`／`.tseg`（試合記録の「チーム成績｜個人成績」）
  - 今回足すベンチのステッパーなど新規の操作部品も四角で作る。
- 対象外（丸のまま）：アバター、状態を示すだけのバッジ（`.notetag`・`.evgroups`・`.chatpaneall`・`.tag.team`・未読バッジ）、トグルスイッチ、ピッチ上のトークン。
- 高さ・余白・色・選択状態の表現は変えない（角だけ）。スマホは変えない。

## 5. CSS の契約（`app/globals.css`）

- 行頭 `@media` は 9 本のまま。新規ルールは基底に、PC だけの調整は PC reset セクションに。色はトークンのみ、新規 hex・グラデーション・絵文字は禁止、文字 12px 以上、スマホのタップ領域 44px 以上、緑（`--primary`）は主ボタンだけ。スマホ 390px で横はみ出しゼロ。

## 6. 受け入れ基準

1. PC の該当 7 画面と戦術ボード／セットプレーのヘッダーにホームへ戻るボタンが無い。画面内の「‹ 戻る」は残る。画面名の左端が揃う。スマホは不変。
2. 戦術ボードの右カラムに「スタメン」のタイルが無く、ベンチ／メンバー外／登録選手の 3 つ。中3 を選ぶと 3 つとも中3 の人数になり、「すべて」で全体に戻る。
3. ベンチの枠数を ＋／− で変えられる。枠を縮めるとあふれた選手がメンバー外へ移る。メンバー外の「＋」でベンチへ、ベンチの「−」でメンバー外へ。満員のときは toast。ピッチへのドラッグ交代と枠から外す操作で、選手が仕様どおりベンチ／メンバー外に入る。旧データ（`benchIds` 無し）は 7 人がベンチに入る。再読み込みで保持される。
4. 戦術ボードの「試合予定にメンバーを登録」で試合の予定に登録でき、予定の詳細にスタメンとベンチが出る。選手（sora@alfafc.example）で開くと自分の立場の 1 行が出る。スタッフは更新・削除できる。予定カードに「メンバー発表」のバッジ。
5. PC で §4 の対象がすべて 8px の角丸になり、対象外は丸のまま。PC 全画面の洗い出しで、操作できる丸い部品が残っていない。スマホの見た目は変わらない。
6. 場所の履歴（既存）が PC・スマホで動く（最近の場所のチップ、選ぶと住所が入る）。
7. `npx tsc --noEmit` 成功、`@media` 9 本、スマホ全画面ではみ出しゼロ。スマホの画面は戦術ボード・予定の詳細以外、変更前（`scratchpad/tools/p4_base/m`）と一致。

## 7. 検証手段

- 開発サーバー http://localhost:3000（落ちていたら `(nohup npm run dev > /tmp/alfa_dev.log 2>&1 &)`）。`next build` 禁止。
- ツール：`scratchpad/tools/`（`mobile_audit.js <outdir>`、`pc_baseline.js <outdir>`、`compare.py <dirA> <dirB> <outdir>`）。丸い部品の洗い出しは `scratchpad/tools/p4_scout/pills.js`。雛形は `p2_verify2/lib.js`。**起動から保存データの読み込みまで 3〜4 秒かかる（スプラッシュ）ので、reload 後は 6 秒待つ。**
- PC のトークンのタップ・ドラッグは `pointerType:"mouse"` のポインタイベントが必要。`window.confirm` は `page.on("dialog", d => d.accept())`。
