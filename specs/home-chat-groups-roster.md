## 2. チャット：お知らせのタブを廃止し、グループのメッセージと「お知らせにする」

### 2-1. 形

- チャットは **1 画面**（「お知らせ｜メッセージ」の切替 `useChatSeg` を廃止。ヘッダーは「チャット」）。会話の一覧は 3 つの区画：
  1. **グループ**：「全員」（キー `grp:all`）、学年グループ（`grp:<id>`）、カスタムグループ（`grp:<id>`）を `team.groups` の順に。行＝色の点（グループの色。全員はネイビー `ALL_TARGETS_COLOR`）・名前・最新の 1 行・右に時刻と未読の数字。
  2. **選手・保護者**：今の 1 対 1（`p:<id>`）の一覧（並び・行の形は今のまま）。
  3. **相手チーム**：今の `opp:<teamId>`（スタッフだけ）。
- 選手・保護者が見る一覧：自分が入っているグループ（全員＋自分の学年＋自分のカスタムグループ）と、スタッフとの 1 対 1。
- 「＋ 新しいメッセージ」（1 対 1 の相手を選ぶ）は今のまま。グループは作らない（グループの追加・編集は設定の「学年・グループ」）。
- PC：左に一覧、右にスレッド（2 列）。今の 3 列目（既読の列）は廃止。何も選んでいなければ先頭のグループ（全員）を開く（R3-3 の「先頭を開く」を踏襲）。
- スマホ：一覧 → 行を押すとスレッドのシート（今の `ChatSheet`）。
- チーム運営のセグメント「チャット」（TeamHub の `ChatHome lockSegment="ann"`）は同じ一覧を出す（お知らせだけに絞る指定を廃止）。

### 2-2. グループのスレッド

- 会話キー `grp:all` と `grp:<groupId>`（`groupThreadKey`）。メンバー＝そのグループの選手・保護者（`playerInGroup`。全員は名簿全員）＋スタッフ全員。
- **選手・保護者も投稿できる**（groups-phase2 §5 の「選手はグループスレッドに投稿不可」は廃止。LINE のグループと同じ）。1 対 1 と同じ入力欄・添付・引用返信。
- 吹き出し：今の 1 対 1 と同じ部品（`ChatThread`）。グループでは相手側の吹き出しに**送信者の名前**（スタッフは「岡本監督」、選手は名前）を出す。
- 既読：`ChatReadState` を広げる：`{ staff?: number; member?: number; members?: Record<playerId, number> }`。グループでは `members[playerId]` に各人の既読時刻、`staff` にスタッフの既読時刻。`markChatRead(key, side)` は選手・保護者なら `members[自分の id]` を更新。
  - スタッフの未読＝自分以外（選手・保護者）の発言で `staff` より新しいもの。選手の未読＝自分以外の発言で `members[自分]` より新しいもの。`unreadCount`／`staffUnreadTotal`／`memberUnreadTotal`（`lib/chat.ts`）をグループに対応させる。
  - 1 対 1 の既読の印（「既読」）は今のまま。グループの吹き出しには既読の印を出さない（お知らせの行だけ §2-4）。
- `sendMessage` は `grp:` 宛を受け付ける（chat-plan-a §1 の「`p:` だけ」を解除）。`removeMessage` はスタッフなら誰の発言でも、選手は自分の発言だけ。
- 通知の数字（`lib/badges.ts`）：`chatBadge` ＝ 1 対 1 の未読＋グループの未読（＋スタッフは相手チーム）。`announcementBadge` は廃止（グループの未読に含まれる）。

### 2-3. 長押し／右クリックのメニュー

- 吹き出しに **PC は右クリック**（`onContextMenu`）、**スマホは長押し**（`pointerdown` → 500ms。動いたら取りやめ。吹き出しに `-webkit-touch-callout: none; user-select: none`）でメニュー `.hp-menu`（R3 の「…」メニューと同じ部品・44px／PC 32px）を出す。
- メニューの項目（**スタッフ・グループのスレッドだけ**）：
  - 「お知らせにする」／すでにお知らせなら「お知らせを解除」
  - お知らせのとき「固定する」／「固定を外す」（固定は最大 2 件。3 件目を固定したら一番古い固定を外す。今のお知らせと同じ）
  - お知らせのとき「既読・了解を見る」（§2-4 のパネル）
  - 「削除」（確認 `window.confirm`）
- 1 対 1 と相手チームのスレッドではメニューを出さない（今のまま）。選手・保護者にはメニューを出さない。
- 「お知らせにする」はトースト「お知らせにしました（ホームに出ます）」。

### 2-4. お知らせの印とデータ

- `ChatMessage` に足す（すべて任意・後方互換）：
  - `announce?: { ts: number; byName?: string }`：お知らせにした時刻と人。
  - `pinned?: boolean`：ホームの先頭に固定。
  - `acks?: Record<playerId, number>`：選手・保護者の「了解」。
- お知らせのメッセージの吹き出し：左上に小さな札「お知らせ」（12px・`--accent-tint` の地・`--accent`）。スタッフにはその下に 1 行「既読 N/M ・ 了解 K ›」（12px・`--mut`。押すと §2-4 のパネル）。選手・保護者にはその下に「了解」ボタン（R3-5 の了解ボタンと同じ：まだ＝青塗り、押した後＝薄い「✓ 了解済み」）。
  - N＝そのスレッドのメンバー（選手・保護者）のうち `members[id] >= message.ts` の人数、M＝メンバー数、K＝`acks` の人数。
- 「既読・了解を見る」パネル：今の `AnnReadPanel` を**メッセージ版**（`MessageReadPanel`）に作り替える。タブ「未読｜既読｜了解」、中身は `PlayersByGrade`（学年見出し＋背番号順）。了解のタブは未了解を上、了解を下（R2-7 と同じ）。PC はダイアログ、スマホはシート。
- 削除したメッセージはお知らせからも消える。お知らせを解除すると `announce`／`pinned` を外す（`acks` は残してよい）。

### 2-5. 廃止するもの

- `AnnouncementsView`、`AnnCard`、`AnnouncementCompose`（お知らせの作成）、`AnnouncementDetail`、`AnnReadSummary`、`AnnReadPanel`（メッセージ版に置き換え）、シート `annDetail`／`annCompose`、`useChatSeg`／`saveChatSeg`／`ChatSeg`、`announcementBadge`、`Announcement` 型と `team.announcements`（移行後は空配列のまま残して型だけ保持してもよい。新規には書かない）、lib/chat.ts の `sortAnnouncements`／`visibleAnnouncements`／`announcementUnreadCount`／`announcementStats`／`applyPinned`／`NewAnnouncementInput` のうち使われなくなるもの。
- 設定の「お知らせ」関連（R3-5 の「お知らせの削除は…へ」など）は対象が無くなるので外す。
- 通知（`lib/notifications.ts`）の「新しいお知らせ：…」は、**お知らせにされたメッセージ**（自分が入っているグループ）から作る（`target: { kind: "message", key, id }`。押すとそのスレッドのその吹き出しへ）。

### 2-6. ホームの「最新のお知らせ」

- 元データ＝お知らせにされたメッセージ（`announce` あり）。スタッフは全グループ、選手・保護者は自分が入っているグループのもの。並びは固定 → `announce.ts` の新しい順。ホームは 3 件、「すべて見る（N）›」でお知らせ一覧（§2-7）。
- 行（今の `.hp-ann` の形を踏襲）：1 行目＝本文の 1 行目（40 字で省略）、2 行目＝「グループ名 ・ M/D」＋ スタッフは「既読 N/M ・ 了解 K」、選手・保護者は「了解」ボタン（未了解のときだけ。押すと `acks` に入る）。固定は「固定」の札。
- 押すと、そのグループのスレッドをその吹き出しまでスクロールして開く（`board.openChat({ key, messageId })`。スマホはシート、PC はチャット画面）。吹き出しは 1.5 秒ほど `--accent-tint` で光る。

### 2-7. お知らせ一覧

- ホームの「すべて見る ›」で開く（スマホはシート、PC はダイアログ。`sheet.type = "annList"`）。見出し「お知らせ」。お知らせにされたメッセージを §2-6 と同じ行で全件（固定 → 新しい順）。行を押すと §2-6 と同じくスレッドへ。チャットの画面にはこの一覧を置かない（「チャット欄のお知らせは廃止」）。

### 2-8. 移行とデモ

- 一度だけの移行（`lib/storage.ts`、完了マーカー `soccer_tactics_chat_groups_v1`）：`team.announcements[]` の各お知らせを `ChatMessage` に変換して `messages` に足す：`to`＝`groupIds` が空なら `grp:all`、あれば**それぞれのグループのスレッド**（複数なら複製）。`from: "coach"`、`fromName`／`fromRole` は元の値、`text`＝`title` があれば `title + "\n" + text`、`attachments`、`ts`、`announce: { ts }`、`pinned`、`acks`（元の `acks` をそのまま）。変換後 `team.announcements = []`。
- 既読は引き継がない（`members` は空から）。
- デモ：`sampleAnnouncements`（3 件）は**グループのメッセージとして**シードし（上と同じ変換）、合わせて 全員 と 中1 のスレッドにスタッフの短い発言を 1〜2 件ずつ入れる（グループが空に見えないように）。

### 2-9. 受け入れ

1. チャットに「お知らせ｜メッセージ」の切替が無く、一覧に「グループ」（全員・中1・中2・中3・Aチーム・Bチーム・GK）・「選手・保護者」・「相手チーム」の区画がある。選手は自分のグループだけ。
2. グループのスレッドでスタッフも選手も送れ、相手側の吹き出しに名前が出る。未読の数字が一覧・レール・下部タブで一致する。
3. スタッフがグループの吹き出しを右クリック（PC）／長押し（スマホ）すると「お知らせにする」が出て、押すと吹き出しに「お知らせ」の札と「既読 N/M ・ 了解 K ›」が付き、ホームの「最新のお知らせ」の先頭に出る。1 対 1 ではメニューが出ない。
4. 選手のホームのお知らせに「了解」があり、押すとスタッフの「了解 K」が増える。「既読・了解を見る」で未読・既読・了解の名前が学年順に出る。
5. 移行：保存済みのお知らせがメッセージになり、ホームと各グループに出る。デモも同じ。
6. 既存の検証が通る（意図した差分は更新）。横はみ出し 0。

## 3. 名簿の絞り込みを複数選択に

- `useGroupFilter("roster")` は元から `string[]`。名簿の絞り込み（`RosterFilterPanel`。PC の左の列とスマホのシート）の **学年とグループを複数選択**にする：行は四角のチェック（`FilterRow shape="sq"`）、押すと追加／除去。選んだグループの**いずれかに入っている選手**を出す（和集合）。ポジション・状態は今のまま 1 つ（丸）。
- 「全員」：学年の区画の先頭に行「全員」（四角のチェック。何も選んでいないとき＝ON。押すと選択をすべて外す）。「すべて解除」も残す。
- 名簿側の使い方：`resolveFilterGroups(rosGroupIds, team.groups)` で複数に解決し、`rosGroup` を使っている所（表示する選手の絞り込み、`.rossel` の文言「中1 ・ Aチーム」、スマホの行の補足「絞り込みと違うグループ」、PC の列の数字）を配列で動くようにする。`rosFilterOn` は 1 つ以上選んでいれば true。
- 他の画面の絞り込み（試合記録・ノート・チャット・戦術ボード）は今のまま。
- 受け入れ：名簿で「中1」と「Aチーム」を同時に選べ、両方に入っている選手が重複なく出る。「全員」を押すと全員に戻る。`.rossel` が「中1 ・ Aチーム」。既存の p14・p18・p24・p29c（名簿の区画は丸→四角＋「全員」）の期待値を更新。

## 4. 実装時の判断（2026-10-29）

Sonnet 3 単位（wp1 ホーム・名簿／wp2 チャットのグループ化・廃止・移行／wp3 メニュー・ホーム・お知らせ一覧）を直列で実装し、Opus 4 観点（spec ホーム・名簿／spec チャット／CSS の契約／動き）でレビュー、残った 8 件（重複を除き 6 件）を統括が直した。検証 `p33a`（32）・`p33b`（84）・`p33c`（49）・`p33d`（9）。

- **ホーム・名簿（§1・§3）**：「全員」の行は学年の区画の先頭（学年が無ければグループの先頭）。各区画の「すべて解除」はその区画だけ、「全員」は両方を外す。`.rossel` と補足の並びは `team.groups` の順。保存済みの絞り込みに削除済みの id が混ざっていたら有効な id だけに書き直す。
- **チャットの形（§2-1）**：選手・保護者の一覧の区画名は「グループ」と「スタッフ」（1 対 1 の行 1 本）。スタッフの「選手・保護者」が空なら「まだメッセージはありません」。「＋ 新しいメッセージ」は一覧の末尾に常設（PC は上にも）。TeamHub のセグメント「チャット」は `lockSegment` を外して同じ一覧。
- **グループのスレッド（§2-2）**：他のスタッフ（`fromName` が違う）の発言は相手側（左）に名前つき。「既読 N/M」の N は `members[id] >= ts` に**了解した人も含める**（ホームで了解した人を未読に数えない）。M はメンバー（発言者本人を除く）。選手の未読＝自分以外の発言、スタッフの未読＝選手・保護者の発言。`staffUnreadTotal` は今あるグループだけ数える。`markChatRead(key, side, memberId)`。`removeMessage` の権限は BoardProvider でも守る。
- **メニュー（§2-3）**：新設の `.hp-menu` ではなく ChatThread 既存の `.chatmenu`（右クリック／500ms 長押し・44px／PC 32px）に「お知らせにする／解除」「固定する／外す」「既読・了解を見る」を足した（スタッフ・グループだけ）。既存の「返信／コピー／削除」は 1 対 1・選手でも今のまま（spec の「メニューを出さない」はお知らせ系の項目に限る）。札「お知らせ」は自分の吹き出し（青地）では白地。`user-select: none` はスマホのシートと `.chatapp:has(.mhead)` の吹き出しだけ。
- **既読・了解パネル（§2-4）**：`MessageReadPanel`（`PlayersByGrade`、再通知は廃止）、シート `msgRead`（PC ダイアログ・スマホ シート）。**スマホで閉じたら元のスレッドに戻る**（`chatTo` を持たせ、`SheetManager` の `closeMsgRead` が `chat` を開き直す。PC は右のペインが残るので閉じるだけ）。パネルの中身は左右 16px。題名は `.sheet h2` の既定（PC の 1 本目のブロックの margin に合わせる）。
- **ホーム（§2-6）**：行は `.hp-annitem`（`button.hp-row` と選手の「了解」を包む）。「すべて見る（N）›」の N は全件、0 件なら出さない。**タイムラインの行は `threadKey`／`messageId` を持ち**、選手のグループ投稿はそのグループのスレッドのその吹き出しへ（文言に「全員：」などグループ名を添える。削除済みグループのスレッドへの発言は出さない）。
- **お知らせ一覧（§2-7）**：`AnnListSheet`（`annList`）。行は `AnnouncementList`（ホームと同じ部品）。
- **移行とデモ（§2-8）**：`migrateChatGroupsOnce`（`lib/storage.ts`。`loadMessages`／`loadTeam` の先頭から。存在しないグループは除き、残りが空なら `grp:all`。複数は `msg_ann_<id>_<n>` で複製。旧 `to: "team"` は `grp:all` へ。`acks` は `playerId[]` → `{playerId: ts}`。`team` が書けなければ `messages` を戻してマーカーを立てない）。旧 TeamProvider の `planChatMigration`（team/grp → お知らせ）と announcement 系 API は削除。デモは `lib/sampleChat.ts`（お知らせ 3 件＋全員に 2 件・中1 に 2 件、既読は `members` で 52/70・20/23・15/16）。
- **通知（§2-5）**：「新しいお知らせ」は了解済みのものを除く（ホームで了解したら消える）。旧「お知らせの引用」（`replyTo.source === "announcement"`）を押すと、移行後の `msg_ann_<元 id>` のスレッドへ（無ければトースト「このお知らせは削除されました」）。
- **直さなかった指摘**：廃止したお知らせの UI の CSS（`.anncard`／`.anndetail`／`.anncompose`／`.annsum*`／`.chatreadcol` など約 420 行）が残っている件（参照 0 で実行時の害なし。次に CSS を整理するときに消す）。
- **既存の検証の更新**：p11（区画ベース・新マーカー）、p25（吹き出しの「既読 N/M ・ 了解 K ›」とパネル、作成シートは「無い」確認）、p28（了解タブ）、p29c（名簿は四角＋「全員」）、p29d（先頭は全員・既読の列廃止・固定の札）、p29f（固定の帯・作成ボタン・削除・了解）、p23（「すべて見る（」の数）、p33b（すべて見る → 一覧のシート）。
